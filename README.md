# multistep_port — operations guide

The plan and the "why" live in [PLAN.md](PLAN.md). This file is how we *work* here:
commands, session protocol, where each kind of progress is recorded.

## Orientation (60 seconds)

- **Goal:** port Kittens Game (orig, immutable, at `../orig_project/kittensgame` @ `781e379`)
  to F#/Elmish.Land in `kittens_land/`, with a deterministic oracle proving equivalence.
- **Unit of work:** a *work unit* (`village-03`), not a file. Layer: `core|shell|data|infra`.
  Status: `not-started → in-progress → translated → verified` (+`blocked`).
- **Truth about status:** `ledger/migration.yaml`. Analysis facts: `analysis/files.json`
  (generated by `node tools/scan.js`). Human dashboards: `reports/progress.md`.
- **Sessions do at most 2–3 work units**, then write `reports/sessions/YYYY-MM-DD-NN-<slug>.md`
  and stop.

## Commands

| Task | Command (from `multistep_port/`) |
|---|---|
| Regenerate orig inventory + nondeterminism scan | `node tools/scan.js` |
| Build new project (fast) | `dotnet build kittens_land` |
| Build production bundle (Fable+vite) | `cd kittens_land && elmish-land build` |
| Dev server | `cd kittens_land && elmish-land server` |
| Run orig's own headless tests (sanity that orig loads) | `cd ../orig_project/kittensgame && npx jest -c jest.config.unittest.json` |
| Compare two oracle snapshots | `node tools/diff-snapshots.js a.json b.json` (when built) |

## Session protocol (paste into every LLM session prompt)

```
You are continuing the multistep port of Kittens Game to F# (Elmish.Land).

1. Read multistep_port/PLAN.md (skim), multistep_port/README.md (this file),
   multistep_port/reports/progress.md, and the LAST session report in
   multistep_port/reports/sessions/.
2. From multistep_port/ledger/migration.yaml pick the next units marked
   not-started whose dependencies are all verified. Work on AT MOST 3.
3. For each unit, in dependency order:
   a. Read its ledger entry (symbols, lines, layer, contract, depends-on).
   b. Read the corresponding orig code (see analysis/inventory.md for what it does).
   c. Implement in kittens_land/ following PLAN.md §6 conversion patterns.
   d. dotnet build must be green. For core units: run the unit's oracle scenario
      and diff against fixtures (oracle/README.md); failures go to
      reports/discrepancies.md — never silently adjust the test.
   e. Update the unit's ledger entry (status, target symbols, verification).
4. Write reports/sessions/YYYY-MM-DD-NN-<slug>.md: units done, files changed,
   tests/oracle results, assumptions, remaining uncertainty, suggested next units.
5. STOP. Do not start a 4th unit. Do not refactor beyond your units.
```

## Where each kind of progress is recorded

| Artifact | File | Who writes it |
|---|---|---|
| Unit statuses, contracts, verification results | `ledger/migration.yaml` | every session (mandatory) |
| Semantic description of orig files | `analysis/inventory.md` | recon sessions |
| Work-unit registry & splitting | `analysis/work-units.json` + ledger | recon sessions |
| Verified static data specs | `analysis/specs/` | spec-verify units |
| Nondeterminism census | `analysis/nondeterminism.json` | `node tools/scan.js` (generated) |
| Deliberate divergences & conventions | `ledger/decisions.md` | anyone, immediately when decided |
| Oracle scenarios / golden fixtures | `oracle/scenarios/`, `oracle/fixtures/` | oracle units |
| Mismatch diagnosis | `reports/discrepancies.md` | any session hitting a mismatch |
| Per-session narrative | `reports/sessions/…` | every session (mandatory) |
| Dashboard | `reports/progress.md` | keep in sync with ledger |

## Rules of the road

1. `orig_project/` is read-only. No exceptions — not even "just a small fix".
2. Never hand-edit `analysis/files.json` / `nondeterminism.json` (generated).
3. `verified` status requires: build green + oracle agreement (core) + ledger updated
   + session report. No shortcuts.
4. Any arithmetic reordering, semantic reinterpretation, or "improvement" over orig
   = a decision entry first, or it doesn't happen.
5. Commit (git) at the end of every session — the ledger is the project's memory.
