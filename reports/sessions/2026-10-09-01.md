## Bugs found on the way

- **Fable rejects `System.Double.IsFinite`** — priceLines (tooltip ETA) used it;
  cold server start failed while warm servers served stale JS. Replaced with
  IsInfinity/IsNaN checks.
- **F# mixed list expressions silently drop bare elements**: any branch mixing
  bare `Html.div [...]` with `yield!` compiles with FS3221 warnings and the
  bare elements DO NOT RENDER (bit the festival button, science checkbox,
  policy panel, religion header/praise). Rule for this codebase now: in any
  list that uses `yield!`, every element gets an explicit `yield`.

## Addendum 4: barn/iron investigation resolution

User-reported "barn does not increase iron storage" could not be reproduced in
the current build (0/50 -> 0/100 verified, +50 per barn). Root cause of the
original observation: the frozen-app bug fixed in load-02 (parseSave crash
killed the Elmish loop) plus the HMR reboot storm — clicks and cap updates
were being lost wholesale. During the audit a REAL same-type gap was found
and fixed: addBarnWarehouseRatio was never ported, so storage-ratio upgrades
(stoneBarns/reinforcedBarns/titaniumBarns/alloyBarns/concreteBarns =
barnRatio; reinforcedWarehouses = warehouseRatio; silos = barn catnip boost)
did nothing. providerEffect now takes a StorageRatioContext read from the
previous cache pass (orig one-rebuild-stale getEffect semantics). fsi E2E:
base 50 + barn 50x1.75 = 137.5 iron cap after stoneBarns.
