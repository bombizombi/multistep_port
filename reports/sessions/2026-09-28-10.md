## 1. DISC-1 SOLVED (first-hunt IDENTICAL)

The starvation boom-bust divergence had four stacked causes, all fixed:

1. **deathTimeout semantics** (`Game.Managers.starvationStep`): orig decrements `deathTimeout` in EVERY starving non-kill tick (it may go negative) and NEVER touches it while not starving; my port reset it to 0 on recovery and skipped decrements when `starved == 0`. Fixed to match js/village.js L455-461.
2. **Kill-tick cache refresh** (`sim.killKittens` tail, village.js L3390-3392): orig calls `village.updateResourceProduction()` + `game.updateResources()` when a kitten dies — the kill tick recomputes the production cache AND perTickCached. The runner now detects the kill and refreshes both.
3. **Happiness consumption branch** (game.js L3810-3817): catnip consumption grows when happiness > 1 scaled by `(1 - freeKittens/kittens)`. The F# production had the branch but the runner never passed live `Happiness`/`Kittens`/`FreeKittens` into the production context.
4. **RNG stream alignment** (D014 extension): the two drivers' streams sit at different positions (orig's bootstrap + ~13.5 draws/tick of pure-seam draws are mirrored nowhere). Weather never rolled in long-run so it never mattered before; hunt loot draws do. first-hunt now re-seeds in the SAME move phase as the hunt (`2300 resop seed …`) so loot rolls compare. This is the documented D014 mechanism; scenario files own the alignment.

## 2. Production cache (structural fix, village-04 amendment)

Orig caches `village.resourceProduction` on a **10-tick timer** (fires ticks 1, 11, 21 — before updateCaches in the timer's handler order), lazily on first read, and instantly on job assignment (`sim.assignJob` tail) / promotion / load — but NOT on unassignment or births. The F# runner now owns an identical cache:

- `prodCache` + `prodPhase` (freq 10) in `execute`, fired before `updateCachesPhase` (freq 5) inside the timer block.
- Instant refresh in the `assign` move only (assignment refreshes, unassignment doesn't).
- `getResProduction` ported in full: engineer `ES<craft>` keys (automationBonus, rank-vs-tier penalty 0.15, skill mod, happiness), rank multiplier via `<job>BoostPerRank`, leader branches as seams.
- `actionAmbassadors(1)` ported (village.js L497-527): culture/spice consumption via `getAmtDependsOnStock`, LDR on `*Chance` keys, `embassyEffectCap` sqrt — feeds `diplomacy.cachedAmbassadorEffects`.

This was a latent divergence: the verified scenarios never crossed a skill-tier boundary between cache refreshes; engineers (workshop-13) would have.
