# Recon: js/calendar.js (1268 lines) — recon unit recon-06

## Description
`com.nuclearunicorn.game.Calendar` (dojo.declared, line 4) is the time engine of the game: it owns the season/year/cycle clock, advances `day` per tick, and drives all per-day random events. It holds the static season table (spring/summer/autumn/winter with catnip production modifiers), the 10-cycle "era" table (charon…kairo with building-effect and festival multipliers), weather rolling and catnip weather modifiers, and festival day countdown. It is also the main randomness consumer: astronomical events (observe button), meteors, unicorn/zebra/alicorn/rift/ivory-meteor rolls, temporal paradoxes, elder unlocks, AI apocalypse decay, and a crypto (bcoin) price random walk. `fastForward` (733-922) is a parallel expected-value (non-random, `Math.round`) implementation of the same daily events used for offline/time-skip. A trivial empty `calendar.Event` class stub sits at the bottom. Note: there is no "mistflow" event anywhere in this file — the random event set is astro/metor/unicorn/zebra/rift/alicorn/ivory.

## Functionality
1. Season table (lines 7-44): 4 seasons with `modifiers` map — catnip x1.5 spring, x1.0 summer/autumn, x0.25 winter; i18n titles.
2. Cycle table (46-214): 5 `cycleYearColors` and 10 cycles (charon, umbra, yarn, helios, cath, redmoon, dune, piscine, terminus, kairo), each with `effects` keyed `"building-effectName"` (gated on numerology perk) and `festivalEffects` (gated on numeromancy + active festival).
3. Time constants (216-237): ticksPerDay=10, daysPerSeason=100, seasonsPerYear=4 / yearsPerCycle=5 / cyclesPerEra=10 computed in constructor (301-308); darkFutureBeginning=40000; mutable state fields incl. legacy unused `futureSeasonTemporalParadox`.
4. Astronomical event pipeline (241-299, 358-385): `observeClear`/`observeHandler` (science + starchart payout with fractional-roll starchart count, line 269)/`observeTimeout` (auto-success roll), `getAreAstroEventsUnlocked` (library on or astronomy), `getAstroEventAutoChance` (SETI=1, observatory effect, astromancy x2, ironWill floor 0.25, cap 1).
5. Cycle effect application (318-356): `cycleEffectsBasics` multiplies building effects by current-cycle values (plus a `sattelite`→observatory upgrade hack), `cycleEffectsFestival` applies cycle festival multipliers x (1+festivalRatio).
6. Helper math (394-415): `giveAlicornmancyYearlyUnicorns` (alicornmancy+pacifism: top up to 2 unicorns every 2 years), `trueYear` (fractional year minus time.flux), `darkFutureYears` (year − 40000 − timeImpedance).
7. `tick` (417-477): per-tick day advance `day += (1 + timeAccelerationRatio)/ticksPerDay` with centiday rounding; flux bookkeeping; int-day-change gate; season rollover (temporal paradox roll here), year rollover (frozen at year>=500 under 1000Years challenge); calls onNewDay → onNewSeason → onNewYear → update in strict order.
8. `onNewDay` (487-731): festival countdown + luxury deficit cancel; void (day<0) or relic income; necrocorn pact daily processing; astro event roll + observe button (300/600 tick timeout); meteor event; pacifism/iron-will unicorn spawns; zebra arrival/departure; unicorn rift; alicorn; ivory meteor; Unicorn Tears overcap enforcement; diplomacy.onNewDay; crypto adjust; authocracy policy hack.
9. `fastForward` (733-922): deterministic expected-value replay of all the above for N skipped days (`Math.round(days * chance)` per event), plus antimatter/temporalFlux per year, spaceBeacon action, millennium paragon, 2-year alicornmancy crossings, statistical void during paradoxes, and a Gaussian-approximated crypto random walk; returns total event count.
10. `onNewSeason` (924-962): resets eventChance; weather roll only from year>3 (warm/cold 175/1000 base, shifted by `coldChance` effect); steamworks unjam at season index 2 with advancedAutomation; pasture re-upgrade.
11. Year rollover (964-1138): `onNewYear` (single year: paragon at year%1000==0, blackPyramid/marker elder-unlock roll, cycleYear/cycle increment with era wrap, antimatter/temporalFlux, AI apocalypse −1%/level on aiCanDestroy resources, even-year alicornmancy) and `onNewYears` (multi-year variant with modulo cycle advance and compounding `1-(1-0.01L)^years` resource decay), plus millennium helpers.
12. Crypto price (1140-1165): `getCryptoPrice` (hodl mode returns `game.server.bcoinPrice`), `adjustCryptoPrice` daily jitter, `correctCryptoPrice` mean reversion above 1100.
13. Weather/season modifiers (1167-1222): `getWeatherMod` (season modifier + warm ±0.15, communism-winter-cold=0, coldHarshness, springCatnipRatio), `getCurSeason` (winterIsComing → eternal winter), season titles with roman numerals.
14. Lifecycle (1225-1264): `resetState`, `save`, `load` (year/day/season/weather/festivalDays/cycle/cycleYear/cryptoPrice incl. legacy field); empty `Event` class stub (1268).

## Port notes / risks
- Day progression formula: per tick `day += (1 + timeAccelerationRatio) / ticksPerDay` (L427) then `day = Math.round(day*100)/100` (L481) — rounding to centiday is load-bearing against float accumulation; season flip subtracts `daysPerSeason` (not modulo) at L444; int-day-change early-return at L437 gates all daily events, so time acceleration only adds extra sub-day ticks, not extra event rolls.
- Flux bookkeeping per tick (L430-435): while `day < 0`, `flux -= 1/(1+ratio)/ticksPerYear`, else `flux += ratio/ticksPerYear` — negative days (paradox) drain flux; `ticksPerYear = 10*100*4 = 4000`.
- Temporal paradox (L450-453): rolled only at season rollover with `Math.random()` (unseeded!); sets `day = -10 - getEffect("temporalParadoxDay")`; during negative days onNewDay gives void instead of relic (L502-508).
- Event probabilities are in OPTK (1/10K per day): astro `(0.0025 + starEventChance) * chronomancy1.1 * timeRatioBonus(1+timeRatio*0.25)`, x2 astromancy (L521-524); meteor `10 * chanceRatio + 40 ironWill` (L566-568); rift 5 OPTK; alicorn 0.2 OPTK x (1 + getLimitedDR(alicornPerTickRatio, 1.2)); ivory meteor 5 OPTK, payout `250 + rand(1500)*(1+ivoryMeteorRatio)` (L691). Ratios recomputed identically in fastForward (L734-736) — extract a shared helper on port.
- observeHandler starchart count handles eventChance>1: `floor(eventChance) + (rand(10000) < frac*10000 ? 1 : 0)` (L267-269) — an expected-value-plus-fractional-roll hybrid, easy to port wrong.
- Weather roll (L928-952): only when `year > 3`; warmChance=175, coldChance=175, both shifted by `1000*getEffect("coldChance")` (LDR-capped), warm checked first on `rand(1000)`; ~65% of seasons get no weather. `winterIsComing` researched-but-not-active zeroes coldChance in winter (L938-940). Catnip modifier: season base + warm 0.15 / cold −0.15; communism+winter+cold → 0; winterIsComing cold multiplies by `1+coldHarshness`; spring by `1+springCatnipRatio` (L1167-1191).
- Festival: this file only counts down `festivalDays` and cancels on furs/ivory/spice deficit when `festivalLuxuryConsumptionRatio` is set (L488-496); festival *start* lives outside (village/diplomacy). Cycle festival multipliers (L341-356) apply only with numeromancy perk AND active festival, multiplied again by `1+festivalRatio`.
- fastForward replaces every random roll with `Math.round(days * chance)` expected values (e.g. L748, 773, 808, 833, 840, 851) — outcomes will diverge from live play by design; keep it exact-match to the original formulas. Crypto skip uses `math.loopOrGaussianApproximation(days-1, false, mean=1.2499270834635280e-6, var=1.4427062504448777e-10, log1p(-1/40000), log1p(1/40000), drawFn)` — the math helper must be ported first.
- Crypto walk: daily step `cryptoPrice += cryptoPrice * (1 - (rand(10) % 3)) * Math.random() / 40000` (L1152) — direction from seeded rand, magnitude from Math.random; mean reversion `*= 0.7 + 0.1*Math.random()` above 1100 (L1159-1160); hodl mode prices from `game.server.bcoinPrice` instead (L1144-1147); whole system gated on `antimatter` researched (L1150, 884).
- onNewYear vs onNewYears cycle advance differs intentionally: single-year increments `cycleYear`/`cycle` with wrap to 0 (L1098-1103); multi-year accumulates `cycleYear += years` with modulo and `(cyclesChange + cycle) % cyclesPerEra` (L1008-1017). 1000Years challenge freezes year at 500 (L457) and caps skipped years in fastForward (L899-901).
- Legacy save-compat traps: `futureSeasonTemporalParadox` round-trips through save/load; `load` uses `||` defaults so a saved `day: 0`/`weather: null` is fine but a saved cryptoPrice of 0 resets to 1000 — replicate defaults exactly.
- Empty `render`/`update` (310-316) and the dojo-only observe-button DOM (L543-555) are shell concerns; `observeRemainingTime` counts ticks (300/600 = 30/60s at 10 ticks/s), not days.
