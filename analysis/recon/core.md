# Recon: core.js (2856 lines) — recon unit recon-17

## Description
core.js is the shell-layer foundation of the Kittens Game UI: a dojo.declare-based control hierarchy (Control → TabManager; ButtonController → ButtonModernController → BuildingBtnController → {BuildingStackableBtnController, BuildingNotStackableBtnController}) paired with view classes (Button → ButtonModern → BuildingBtn → {BuildingStackableBtn, BuildingResearchBtn}), plus Panel/tab layout classes, the global UIUtils tooltip system, and the Console message log. Most of it is DOM plumbing, but four pieces are load-bearing for CORE game logic and must be ported with exact fidelity: (1) `BuildingStackableBtnController.getPrices` — the building price formula with `priceRules`, per-resource `CostReduction` effects and `priceRatio^val` growth; (2) the `payPrice`/`refund`/`payPriceForUndoRefund` path that drives the undo feature (sign-inverted refund payment, `refundPercentage`, `isRefundable`/`isTemporary` checks); (3) `filterMetadata`/`loadMetadata` — the recursive save/load serialization pair used by all 15 managers (59 call sites across js/); (4) the TabManager effect-cache pipeline (`updateEffectCached`/`updateMetaEffectCached`/`getMetaEffect`) that aggregates per-manager effects into `game.globalEffectsCached` with limited-diminishing-return handling, plus the `getMeta` linear-lookup helper backing all metadata access. `build()` in the stackable controller is also gameplay-heavy (construction loop, `breakIronWill` side effects, unlocks, `calculateEffects`). Every manager in js/ inherits from TabManager and every UI button flows through this file's controller chain, so it is the first file to port.

## State & determinism
- Mutable state: `Console.messages` (40-message ring) and `messageIdCounter` (monotonic), `Console.filters` (saved to save file via `console.save`); TabManager `effectsCachedExisting`/`meta`/`panelData` (panel collapse is in-memory only — not serialized anywhere in js/); per-item `meta.totalEffectsCached` (recomputed each cache cycle); `game.globalEffectsCached` is mutated in place as a cross-manager accumulator (zeroed per manager during `updateEffectCached`); `game.tooltipUpdateFunc`/`game.tooltipOwnerDomNode` set by UIUtils; button models are transient (rebuilt in every `fetchModel`/`update`/tooltip hover); view classes cache DOM nodes (`domNode`, `tooltip`, `sellHref`, `toggle`, `add`, `remove`).
- Dojo prototype pitfall: fields written in the class literal are SHARED statics across instances (explicitly documented at TabManager lines 41-53); correct pattern is null field + constructor init.
- Randomness/time usage: none — no `Math.random`, no `Date.now`. The only clock-adjacent code is `calendar.year.toLocaleString()` for console message display (line 555), derived deterministically from game state. Confirmed none.

## Port notes / risks
- `BuildingStackableBtnController.getPrices` (2177-2207) is THE building-price formula the F# port must replicate bit-for-bit: `val = base * (perResourceRatio || ratio)^meta.val * resPriceModifier * priceModifier` where both discounts are `1 - getLimitedDR(getEffect(name+"CostReduction"), 1)`; the `meta.priceRules` branch changes ratio resolution per resource. Multiply order and float ops matter.
- `payPrice` (791-794) delegates to `resPool.payPrices` then refreshes `model.prices` from `getPrices`; the refund family (`refund` 886-901, `payPriceForUndoRefund` 796-813) is the undo backbone: only `res.isRefundable(game) && !price.isTemporary` refunds, scaled by `model.refundPercentage` (default 0.5); the undo variant ADDS the negative amount (`-price.val * refundPercentage`) — sign inversion is load-bearing.
- `filterMetadata` (337-362) + `loadMetadata` (294-327) are the save-compat pair used by all managers; `loadMetadata` is recursive, skips `name`, warns on unknown fields, and deep-loads nested objects. The F# serializer must reproduce field lists/replacers exactly or old saves break.
- Effect caching is order-sensitive: `updateEffectCached` writes into the shared `game.globalEffectsCached`, zeroes `effectsCachedExisting` while iterating, and applies limited DR to whole aggregated demand ratios (catnipDemandRatio, fursDemandRatio, ivoryDemandRatio, spiceDemandRatio, unhappinessRatio) — per-effect diminishing was a historic bug, keep whole-aggregate semantics.
- `BuildingBtnController.getNextEffectValue` (1797-1811) temporarily mutates `metadata.on`, re-runs `updateEffects` + `calendar.cycleEffectsBasics` twice, then restores — a mutation-based what-if; port as pure recomputation of effects at `on+1` vs `on`. Same recalc pattern in `metadataHasChanged`.
- `build()` (2357-2419) is the ultimate construction entry despite living in core.js: limitBuild clamp, pay-per-unit loop, `breakIronWill` bundle (liberty policy recalc, zebraOutpost unjam+recalc, upgrade of sharkRelationsBotanists/huntingArmor/bolas/compositeBow, `diplomacy.onLeavingIW`), `unlocks`, `unlockScheme`, `calculateEffects`+`cycleEffectsBasics`. `incrementValue` (2421-2434) auto-on rules depend on `paragon` count.
- Inheritance chains must be preserved in order: controllers `ButtonController → ButtonModernController → BuildingBtnController → {BuildingStackableBtnController, BuildingNotStackableBtnController}`; views `Button → ButtonModern → BuildingBtn → {BuildingStackableBtn, BuildingResearchBtn}`. Note mixed `this.inherited(arguments)` and explicit `this.inherited("methodName", arguments)` styles — F# needs explicit base-class delegation everywhere; dojo auto-chains constructors only.
- Model caching pitfall: models are transient views — refetched on every render/update AND every tooltip hover (`ButtonModernHelper.getTooltipHTML` re-runs `fetchModel`+`fetchExtendedModel`); do not persist them. Conversely, deprecated `adjustPrice`/`rejustPrice` (762-789) mutate `price.val` in place; base `ButtonController.buyItem` even calls `adjustPrice(model.priceRatio)` with a shifted argument (ratio undefined → would produce NaN) — dormant dead path since all building purchases go through the stackable override; do not port the bug, but note `getPrices` must return fresh copies (the not-stackable controller deep-copies via `$.extend(true,[])` for this reason).
- Async buy flow: `buyItem` can return `{itemBought:false, reason:"require-confirmation", def: dojo.Deferred}` (Iron Will break, buy-all confirm) — the F# port needs a continuation/callback or deferred equivalent; result `reason` strings ("paid-for", "already-bought", "cannot-afford", …) are part of the observable contract (queue/undo/UI rely on them).
- Pure DOM/shell (no gameplay math, port as UI components): Button/ButtonModern/BuildingBtn view classes, ButtonModernHelper, UIUtils, Panel/tab/ContentRowRenderer/Spacer/mixins, Console rendering (but keep its filter state + save/load). Minor quirks to drop: leftover `console.log("this after render", this)` (1131), `classname` typo in `dojo.create` (1086), commented-out `getEffect` block (231-251).
