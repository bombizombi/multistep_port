# Recon: js/toolbar.js + js/preview.js + js/jsx/* (~2560 lines) — recon unit recon-19

## Description
This unit covers the top toolbar (both the deprecated Dojo `js/toolbar.js` and its React replacement `js/jsx/toolbar.jsx.js`), the read-only kgnet save-preview bootstrapper (`js/preview.js`), the left column resource/craft UI (`js/jsx/left.jsx.js`), the chronological time-queue UI (`js/jsx/queue.jsx.js`), and the end-game chiral terminal (`js/jsx/chiral.jsx.js`). Gameplay-visible behavior lives in several places: the winter catnip advisor warning (left.jsx.js L883-893, driven by the cached `game.winterCatnipPerTick`), the energy deficit vs winter-deficit warning classes, the pollution-level warnings, the BLS sorrow indicator, and the queue item add/remove/reorder links that mutate `game.time.queue`. State-mutating controls also include craft shortcuts (`game.craft`/`game.craftAll`), fast hunt/explore/praise/sacrifice links, resource visibility toggles, and the kgnet login/cloud-save actions. By contrast, most of WResourceRow/WCraftRow rendering (colors, weather modifiers, easter-egg classes, per-tick formatting) and the toolbar tooltips are pure display. The legacy Dojo toolbar is explicitly deprecated ("keeping it here in case some 3rd party scripts rely on this") and duplicates the React icons with subtly older formulas. Preview mode is a boot-time mode: `?saveId=` triggers storage detachment and a read-only game load.

- Called by: `index.html`/boot path invokes `Preview.getSaveId()`/`Preview.detachStorage()` before GamePage exists (statics on constructor, preview.js L158-161); `game.server.downloadPreview/loadSave/pushSave*` (server.js, outside unit); `ui.js` L659 publishes `ui/update` each tick, which WLeftPanel/WToolbar/WQueue/WChiral subscribe to for re-render; `left.jsx.js` globals are consumed by `ui.js` (left panel mount); toolbar.js is referenced by no current code path (3rd-party compat only).
- Cross-unit: `game.winterCatnipPerTick` is computed in game.js L2658 and cached on GamePage (L2398); queue engine (pushBack/pushFront/remove/addToQueue/cap) lives in js/time.js L2036-2320.

## State & determinism
- Mutable state: `game.previewMode` (set once at boot); `window.LCstorage` globally replaced by an in-memory shim during preview; `server.motdFreshMessage` mutated inside `ToolbarMOTD.getTooltip()` (side effect in a tooltip getter); `WToolbarPollution` mutates its own `this.message`/`this.freshMessage` during render; `WResourceRow`/`WCraftRow` cache `oldVisibility` and abuse `refs.isTooltipAttached` as instance flags; `res.isHidden`/`res.isHiddenFromCrafting` and `resPool.showHiddenResources` toggled directly from UI; `map.currentBiome` assigned by exploreLast; queue order mutated via time.queue; React local state (isCollapsed/isEditMode/isExpanded/showActions/linkCopied/isLoading/command).
- Time usage: `new Date().getTime()` for lastBackup age (toolbar.jsx.js L729) and `toLocaleDateString` for save records (L572); no RNG anywhere in the unit. All game-state math is deterministic reads of engine caches (`energyProd/energyWinterProd/energyCons`, `winterCatnipPerTick`, `cathPollution`).
- React components are re-rendered per tick via the `ui/update` publish with the whole `game` object pushed through `setState` — a "state = entire game" pattern.

## Port notes / risks
- Read-only gating is a single flag: `game.isReadOnly()` returns `this.previewMode` (game.js L2846-2847); preview.js sets it before `game.load()`. UI mutators gate on it in left.jsx.js (craft shortcuts L502-505, hunt/explore/sacrifice/praise L870-950, WPins L952) and toolbar.jsx.js (WLogin L820, WToolbarFPS L265), but queue.jsx.js never checks it — preview safety there relies on tab-level gating elsewhere; an Elmish/Fable port should centralize this as a `ReadOnly` flag in the model rather than scattered null-returns.
- Preview's load-bearing safety is `previewDetachStorage()`: all save writes during preview go to a detached shim carrying over only the `ui` and `language` keys. A Fable port must replicate the storage-abstraction seam (a Storage interface swapped at boot) and `game.start()` refusing the tick loop in read-only mode while still refreshing tab markers.
- The legacy `js/toolbar.js` is explicitly deprecated and kept only for 3rd-party scripts; its formulas are stale relative to toolbar.jsx.js (raw `karma.value` vs `village.getHappinessFromKarma()`, no `consumableLuxuryHappiness`, no challenge-adjusted base). An Elmish/Fable port can drop toolbar.js wholesale and implement only jsx-07 semantics; a faithful line-port must keep both divergent branches.
- Elmish/Fable replaces the React class components and the `dojo.subscribe("ui/update")` push-the-whole-game pattern with the dispatch/update loop; `shouldComponentUpdate` visibility hacks (oldVisibility caching) and per-tick tooltip re-attachment become plain render predicates + subscription-based tooltips.
- Side effects in getters need restructuring: `WToolbarMOTD.getTooltip` clears `motdFreshMessage` and `WToolbarPollution.render` mutates fresh-message tracking — convert to messages/commands in an Elmish port.
- Winter catnip advisor (left.jsx.js L883-893) depends on `game.winterCatnipPerTick` being precomputed each tick in game.js L2658 (catnip production with winter modifiers); the port must keep this cache warm or recompute on demand, and note it is also consumed at game.js L4649 (outside this unit).
- Queue UI ↔ time-queue interplay: `addToQueue` clamps amounts to `cap - queueLength` (time.js L2216), item options are alphabetically sorted per the persisted `alphabeticalSort` flag, tooltips resolve controller/model via `getQueueElementControllerAndModel` and reach into `ButtonModernHelper`/`EmbassyButtonHelper` — the queue port needs those helpers' contracts (recon units for time.js/buttons).
- Pure-display oddities to preserve or consciously drop: easter-egg resource value classes (420/666/1337/...), slab/scaffold trade-icon proxies, temporal-paradox "???" per-tick, pollution "fresh message" animation class, and the -100% weather-modifier clamp.
