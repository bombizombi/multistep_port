# Recon: game.js (6432 lines) — recon unit recon-01

## Description
game.js is the game's root orchestrator. It defines five small dojo classes (`Timer`, `Telemetry`, `Server`, `UndoChange`, `EffectsManager`) and then the monolithic `GamePage` (lines 2183-6431), exposed globally as `gamePage`/`game` by index.html's `initGame()`. GamePage's constructor wires every subsystem: it constructs `resPool`, `calendar`, `village` first, then 13 more managers from a fixed-order list (`challenges, workshop, diplomacy, bld, science, achievements, religion, space, time, prestige, stats, void, settings` — challenges deliberately before space), then instantiates 11 UI tabs from a `tabRegistry` (+ mobile QueueTab, separate SettingsTab) and registers ~10 recurring `Timer` events. Central mutable game state lives on GamePage itself (`opts`, karma/ironWill flags, `globalEffectsCached`, `ticks`, `undoChange`) plus the manager references; the tick pipeline is: a 200 ms `setInterval` or Blob-WebWorker fires `tick()` → scheduled events + undo TTL → `update()` (autosave countdown, `updateModel()` run once or twice under time acceleration, `time.update()`, `ui.update()`) where `updateModel()` calls each manager's `update()` in a fixed order, syncs the kittens pseudo-resource, advances pollution, and fires the recurring Timer handlers. Production is computed by `calcResourcePerTick` (an ~170-line hand-rolled formula over cached global effects), duplicated for tooltips by `getResourcePerTickStack`. Save/load serializes every manager under its own top-level key of one localStorage blob (version 15) with LZ compression over 5 MB, plus a v1→v14 `migrateSave` chain and a hand-built post-reset save in `_resetInternal`. Interaction with js/* files is everywhere: game.js owns dispatch (`unlock`/`upgrade`/`getUnlockByName`, `getEffect`), lifecycle (save/load/reset fan-out to all managers) and formatting helpers managers call back into.

## Functionality
1. `Timer`: tick-phase scheduler — `addEvent(handler, frequency)` fires handlers every N ticks via countdown phases; `scheduleEvent` defers one-shot callbacks (save/load/reset/import) to the top of the next tick so they never land mid-update; `beforeUpdate`/`afterUpdate` collect wall-clock tick-duration stats (71-143).
2. `Telemetry` (+ `IDataStorageAware` dojo mixin subscribing to `server/save`/`server/load` topics): generates and persists an rfc4122 guid, wires New Relic release/attributes/error handler (unlocks the `ghostInTheMachine` badge), `logEvent`/`logRouteChange` no-ops in read-only preview (145-271).
3. `Server`: KGNet cloud mediator — XHR helper with credentials and 403 session invalidation, MOTD fetch from server.json, user profile sync, cloud save push/download/preview, chiral client commands, hodl-mode b-coin price feed from coingecko, `save()` hook writing `motdContent`+`bcoinPrice` into the save (281-632).
4. `UndoChange`: one undoable player action = `{managerId, data, description}` list plus a TTL consumed by the tick loop (637-694).
5. `EffectsManager`: derives display metadata for resource-shaped effect names (`xxxPerTick`, `xxxMax`, `xxxRatio`, …) by prefix-splitting against the resource pool, else looks up a ~400-entry hand-written statics table of effect titles/types (perTick/ratio/perDay/energy/hidden) (699-2177).
6. GamePage constructor: builds console/telemetry/server/preview/math, resource pool + calendar (with `dojo.byId("calendarDiv")` DOM node) + village, instantiates the 13 managers in fixed order from a data table, constructs the 11-tab registry (+ QueueTab on mobile, SettingsTab separate) storing handles like `game.bldTab`, registers recurring timer events (village production every 10 ticks, `updateCaches` every 5, policy recalc 25, achievements 50, winter catnip 25, time queue 10, server refresh/heartbeat/checkForUpdates every 5-10 game-minutes) (2183-2635).
7. Platform/feature-flag plumbing: `getPlatform`/`isMobile` from `window.KGVersion`, `getFeatureFlag` reading a beta/main/mobile table (all true on localhost), fields `featureFlags` (2406-2456, 2641-2654).
8. Effect cache pipeline: `getEffectMeta` (dynamic→statics→bare fallback), `getEffect` reads `globalEffectsCached`, `updateCaches` wipes the cache and calls `updateEffectCached` on workshop/religion/bld/challenges/prestige/space/time/village/science, then `bld.cacheCathPollutionPerTick` and `updateResources` (2673-2717).
9. Diminishing-returns math: `getLimitedDR` (hyperbolic cap: first 75% of limit undiminished, last 25% asymptotic) used for storage and zebra karma; `getUnlimitedDR`/`getInverseUnlimitedDR` sqrt curve for karma (2726-2746, 5892-5906).
10. Tick loop: `start()` prefers a Blob WebWorker posting `tick` every 200 ms, falls back to `setInterval`; `tick()` runs scheduled events + undo TTL even when paused, early-returns to `ui.update()` while paused, else `update()` + `calendar.tick()` + `ticks++` + 5-slot rolling FPS accounting with a per-minute telemetry fps event; `update()` decrements `ticksBeforeSave` (autosave every 400 ticks ≈ 80 s), runs `updateModel()` twice when time is accelerated and `ticks%2==0` (the documented "hack"), then `time.update()` + `ui.update()`; `updateModel()` = resPool.update → bld.update → `village.maxKittens=floor(maxKittens effect)` → village/workshop/diplomacy/religion/space/challenges updates → resCons hack → `bld.cathPollution += cathPollutionPerTick` (clamped ≥0) → kittens pseudo-resource sync → `timer.update()` fires the recurring events (4453-4541, 5238-5389).
11. Production calculation: `calcResourcePerTick(resName)` — the authoritative per-tick formula: PerTickBase + space base × spaceRatio (factory spaceManufacturing hack), season/weather modifier, village job production × Holy Genocide scaling, job/global/building/religion/super ratios, steamworks coal hack, paragon ratio (zeroed for catnip under winterIsComing), catnip pollution, magnetos × steamworks boost, reactor productionRatio, solar revolution × pollution, CMBR flat 0.2 (unless disabled/coal), the 4-step `paragonSpaceProductionRatio` folded into space autoprod with `prodTransferBonus`, festival cycle effects, PerTick×PerTickRatio, village consumption with happiness/anarchy demand, necrocracy+sorrow, pyramid ratios, policy ratio; NaN-guarded to 0 (3666-3837).

## Port notes / risks
- `calcResourcePerTick` (3666) and `getResourcePerTickStack` (3873) are hand-synced duplicates of the same formula — the file literally annotates "extra-compare with this.calcResourcePerTick". An F# port should derive the tooltip stack from one engine, but until then any divergence silently corrupts tooltips; note the flat version applies consumption via `+=` at the very end while the stack interleaves differently, and the stack has extra rows (PerTickCon, engineer craft/consume, exploration, time acceleration ratio) the flat number does not.
- Effect values are eventually-consistent: `getEffect` reads a cache rebuilt every 5 ticks by `updateCaches`, with a fixed manager order (workshop, religion, bld, challenges, prestige, space, time, village, science) that matters because later updateEffectCached calls read earlier entries; `upgrade` wraps recalcs in updateCaches before AND after so cross-feeding effects settle over two passes.
- Ordering constraints in construction: challenges must be instantiated before space (comment at 2485); resPool.setVillage before anything reads consumption; load() replays manager loads in the same fixed order then a second afterLoad pass — port must preserve both orders or saves interact wrong.
- Save format gotchas: `saveVersion = 15`; `JSONreplacer` drops undefined values (key existence semantics matter); LZ-UTF16 compression kicks in >5 MB or `opts.forceLZ` and the loader sniffs a leading `{` for raw JSON vs compressed; `migrateSave` (v1→v15) does real cross-manager surgery and must be kept byte-compatible for old saves; `_resetInternal` bypasses normal save/load entirely and hand-writes the post-reset blob (sqrt-carryover for craftables, resStasisRatio, cryochamber kittens, karma zebras, loadouts) — the single most delicate save-format code; `currentSaveIsBroken` must gate autosave or broken saves get overwritten.
- Hidden DOM/global coupling: Calendar is constructed with the live `#calendarDiv` node; `togglePause` writes `pauseBtn.innerHTML`; `saveUI` animates `#saveTooltip`; `clearLog`/`toggleFilters` touch `#gameLog`/`#logFilters`; jQuery ids `#importData`/`#download-link`/`#optionsDiv`; `dojo.publish` topics are the mod API and `_publish` has a dojo-1.6 arg-wrapping quirk; LCstorage and `$I` are globals.
- Read-only preview (`previewMode` via isReadOnly) short-circuits every mutating entry (save, load, reset, wipe, export/import, cloud, pause, undo, telemetry) — port it as an explicit mode flag checked at the same ~20 entry points, and note `start()` takes a completely different no-timer path in preview.
- Accelerated time is a parity hack: `update()` runs `updateModel()` twice when `time.isAccelerated && ticks % 2 == 0`, while `time.update()` runs once and UI stays at 5 fps-equivalents; `getTicksPerSecondUI` (5 × 1.5) is used only for display countdowns. Porting this as "2× tick rate" changes kitten growth/birth schedules.
- `Timer.handlers`/`scheduledHandlers` are prototype-shared arrays in the dojo literal (all Timer instances would share them — benign today since only one Timer exists, but a port must make them instance fields).
- Special-case hacks to preserve exactly: steamworks `xxxRatioGlobal` coal-only reduction, `paragonSpaceProductionRatio` accumulated across 4 disjoint branches (magnetos/reactors/solar revolution) and only applied to space autoprod via `prodTransferBonus`, CMBR flat +20% excluded for coal, winterIsComing zeroing paragon for catnip, kittens pseudo-resource values overwritten from village in updateModel, `getLimitedDR` maxUndiminished 0.75/0.25 split.
- `unlock()` iterates each type's id list backwards and silently skips unknown ids with console.error — mod saves can reference metas that no longer exist; the port's dispatch table must tolerate unknown (id, type) pairs identically.
