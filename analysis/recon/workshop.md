# Recon: js/workshop.js (3538 lines) — recon unit recon-04

## Description
This file defines `classes.managers.WorkshopManager` (a `TabManager` subclass) holding all static game content for the Workshop tab: 143 upgrade definitions (the brief said 142; counted 143), 23 craft recipes (brief said 20; counted 23), and 8 "zebra" upgrades, each as a plain object literal with name/label/description (`$I` i18n keys), effects, prices, unlock chains, and occasional behavior hooks (`handler`, `calculateEffects`, `evaluateLocks`). The manager implements the buy/craft/unlock logic: `craft()` applies `game.getResCraftRatio(res)` as `craftAmt = amt * (1 + craftRatio)`, pays prices, registers undo events, and triggers building upgrades; `getCraftPrice()` special-cases `ship` (satnav starchart discount) and `manuscript` (Tradition policy). Engineer (timed) crafting converts assigned kittens into fractional crafts per tick via `progressHandicap` and per-tier craft ratios, with consumption accounting in `getConsumptionEngineers`. `fastforward()` also computes `effectsBase` for oilMax/scienceMax/cultureMax/faithMax. The last third of the file is UI: `UpgradeButtonController`, `CraftButtonController`, `CraftButton`, `ZebraUpgradeButtonController`, and the `tab.Workshop` class (dojo-based DOM rendering).

## State & determinism
- mutable state: `upgrade.unlocked`/`researched`, `craft.unlocked`/`value` (assigned engineers)/`progress` (fractional timed-craft progress)/`isLimited`/`isLimitedAmt`, `hideResearched`, `effectsBase` {oilMax, scienceMax, cultureMax, faithMax}, `metaCache` (memoizes `get` lookups, with a pre-existing bug: caches under the queried `upgrade` variable, not `upgradeName`); critically, static definition objects are mutated in place at runtime — `calculateEffects` rewrites `self.effects` tables, `alicornStable` rewrites its own `description`, `advancedRefinement`'s handler rewrites `getCraft("wood").prices`. In F# these must be per-save instance data, not shared statics.
- randomness/time usage: no `Math.random` and no `Date`/wall-clock use anywhere in the file (confirmed). Time enters only as `daysOffset * calendar.ticksPerDay` from the game loop; all progression is a pure function of tick count plus resource/effect state, so the logic is deterministic. Save/load round-trips `craft.progress` as a float.

## Port notes / risks
- `getResCraftRatio` is defined in game.js, not here; `craft()` applies it as `craftAmt = amt * (1 + craftRatio)` — port the game.js formula together with this file, and honor `ignoreBonuses: true` on the wood recipe (UI also subtracts global craftRatio for wood display).
- `progressHandicap` semantics: it only slows engineer crafting — per-tick rate is `kittenResProduction * tierCraftRatio / (600 * ticksPerSecond * progressHandicap)` ("one (bonus/handicap) crafts per engineer per 10 minutes"); defaults to 1 when undefined (set in `resetState`); ranges from 1 (wood/beam/slab/parchment) to 7500 (bloodstone) / 10000 (tMythril); UI difficulty display is `-100 * (1 - 1/handicap)`%.
- `getCraftPrice` special cases: `ship` starchart cost reduced by `getLimitedDR(satnavRatio * sattelite.on, 0.75)` (clones prices); `manuscript` under the Tradition policy returns a hardcoded `{parchment: 20, culture: 300}`; wood prices are mutated to `{catnip: 50}` by the `advancedRefinement` handler and reset in `resetState`.
- `craft()` has a negative-amt guard ("prevent undo giving free res") and undo refunds the actually-gained amount (`actualAmtGained` from `addResEvent`), deliberately using the craft ratio captured at craft time to prevent leader-switch exploits — preserve exact rounding behavior.
- Unlock chains: `unlocks.upgrades` arrays propagate through `game.unlock`; four `evaluateLocks` closures gate upgrades on other researched flags (`stasisChambers`, `tachyonAccelerators`, `transportSuperposition`, `rangefinders`); `resetState` hardcodes initially-unlocked names (6 upgrades, 8 crafts) — keep the lists in sync when splitting data files.
- Handlers run both on research and again during `load` for already-researched upgrades (comment: "just in case") — handler logic must be idempotent in the F# port.
- `fastforward` computes unrelated caps (scienceMax incl. compendia cap/ironWill x10/blackLibrary boost, cultureMax via UDR(0.01), faithMax via threshold+log scaling, oilMax = floor(tankers*500)) inline with a "poor place for this" TODO — port faithfully or relocate deliberately, since balance depends on exact order.
- `craftByEngineers` caches `isLimited`/`isLimitedAmt` storage-limit flags used for UI styling and skips crafting when limited; progress is capped by `_getCraftAllCountInternal` before integer flooring.
- In-place mutation of static defs (effects, description, prices) is the biggest structural risk: F# needs an instance model per save, and `metaCache.get` has a latent bug (caches under wrong key) worth noting but not replicating.
- UI hook cross-module effects to keep: Unicorn Tears challenge injects unicorn/tears prices by weighted cost in `UpgradeButtonController.getPrices`; ironWill gates `manpowerMax` bonuses; carbonSequestration purchase unlocks the `betterSafeThanSorry` achievement.
