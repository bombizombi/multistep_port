# Recon: js/diplomacy.js (2232 lines) — recon unit recon-10

## Description
Defines `classes.managers.DiplomacyManager` (lines 4-1250), the trade/diplomacy subsystem of Kittens Game: eight race definitions (lizards, sharks, griffins, nagas, zebras, spiders, dragons, leviathans) with static buy/sell catalogs, seasonal price modifiers and embassy costs, plus all trade execution math (fuzzy yields, failure/bonus rolls from standing, spice/blueprint/titanium side-rolls). It also owns embassy purchasing economics (1.15x exponential prices, cheap-embassy selection for the time queue), the leviathan "elders" visit mechanic fed by necrocorns, blackcoin buy/sell, an anti-RNG-exploit bookkeeping scheme tied to the undo system, and dynamic per-day mutation of shark trades (`updateSharkScribes`). The remainder of the file (1253-2232) is the Dojo UI layer: race panels, trade and embassy buttons with a custom tooltip showing trade chances, explorers button, blackcoin crash button, and the Diplomacy trade tab. Race standing is a static per-race field in this version — there is no per-season decay of standing; "attitude" shown in the UI is recomputed each render from `getFinalStanding`. Seasonal variation instead enters as a per-resource yield multiplier from the `seasons` maps in the race data.

3. ## Port notes / risks
- Yield formula order is load-bearing (932-933): `(fuzzedNormal + fuzzedBonus*1.25) * sellResource.value * tradeRatio * raceRatio * resourceSeasonTradeRatio * tradeVolume` — bonus trades worth 1.25x; the tab's display average (2060) omits the 1.25 and shows range avg x (1 ± width/2); keep formulas in sync with display.
- `_fuzzGainedAmount` (994-996) is `amount + width*(irwinHallRandom(amount) - amount/2)`; Irwin-Hall over `amount` uniform draws means per-trade RNG cost scales with trade count — F# port must reproduce distribution (or at least mean) and its interaction with undo replays.
- Standing has no decay in this version: it is a static race field; `getFinalStanding` (1111-1128) is asymmetric — hostile capped at 0 (can never become friendly), neutral races only gain via `lizardRelationsDiplomats` with the `(bonus-0.25)/3` transform, friendly get half the bonus. "Attitude" is a pure render-time label.
- Embassy price formula appears twice (388 and 1586): `base x (1 - embassyCostReduction) x 1.15^(embassyLevel + embassyFakeBought)`; source comments explicitly warn the duplication must stay in sync — factor into one shared function in F#.
- Chance pipeline: `getResourceTradeChance` (1143-1161) = `(chance + ambassador tradeNormalResChance)`; <=0 means ambassador-gated (return 0); else x `1 + getLimitedDR(embassyLevel*0.01 [0.0025 IronWill], 0.75 + embassyEffectCap)`. Spice is unique: chance >100% converts into a yield multiplier (947-949), no other resource does this.
- `nonRandomTrades` anti-exploit spans three places (undo 780-781, onNewDay 723-727, consumption in tradeImpl 869-871/914-917/939-969/978); nonRandom trades always take worst outcome for failure rolls but NOT for amount fuzz (comment 927-928) — port all pieces together or undo-based RNG scumming changes behavior.
- `updateSharkScribes` iron-cost bucketing (569-582) uses overlapping thresholds (<301/<501/<1501/<2501/<10001) with different rounding steps and a hard 11111 cap / 125 floor; parchment/manuscript values scale with `year + trueYear` (+4000 when `!startedWithoutChronospheres`), x(1+0.03*blackLibrary).
- Zebra unlock path: `ship >= 1` in `unlockRandomRace` (501-507) which also force-unlocks caravanserai and both zebra relation policies; zebra `unlocks.policies` data (269-271) is applied via generic `game.unlock` on first trade (863-865); titanium side-roll (962-971) depends on ship count and `zebraRelationModifier` x tradepost tradeRatio.
- Leviathans guard everything on `race.embassyPrices` being present (no embassies for elders): chance/volume formulas branch on it (1141, 1157); visit lifecycle (unlockElders 707-718, trade duration cap 884, onNewDay departure 731-743) and `feedElders` marker cap must stay mutually consistent; `sellBcoin` (1212) contains a real misplaced-paren bug (msg receives one argument) — decide fix vs. parity.
- Naming trap: buys use `val`, sells use `value`; shark sell entry is misspelled `compedium` (93) as a resource id; selling sharks' catnip entry (index 1/2 lookups at 533-534) is hard-coded by array position — fragile coupling to the data table ordering.
