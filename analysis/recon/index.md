# Recon: index.html + emulator.html + tests.html (~850 lines) — recon unit recon-20

## Description
index.html is the single page shell that boots the whole game. Static script order in `<head>`: react.min.js, jQuery, dojo.xd.js, lz-string.js, md5.js, system.js; then an inline `SystemJS.config` block registers the babel transpiler plugin (JSX UI modules are transpiled in-browser). An inline block defines the boot helpers (`loadModule`/`_import`/`loadTheme`), and inside `dojo.addOnLoad` a promise chain runs: fetch version.json + build.version.json → import `config` (then preload all color-scheme CSS from `classes.KGConfig`) → import `i18n` and run `i18nLang.init` → import `core` → sequentially System-import 26 game modules → call `initGame()`, which constructs `com.nuclearunicorn.game.ui.GamePage`, attaches `classes.ui.DesktopUI("gameContainerId")`, loads the save and starts the tick loop. The body is the static DOM skeleton: `#gamePageContainer` with top bar, loading screen, the three-column `#game` layout (left resources / mid panels / right log+calendar+queue) and the option/import/export/app/credits dialogs. The managers created later hard-reference many of these ids, so the DOM must exist before `initGame` runs. emulator.html is a dev-only mobile-view wrapper (two device frames iframing `index_v2.html` on port 9999) and tests.html is a Jasmine 2.5.2 spec runner that System-imports `core` plus most game modules and `test/spec/game-spec` without config/i18n.

## Dependencies
- Static head order matters: react before the jsx modules compile; jQuery is used immediately by inline boot code (`$("#loadingProgressBar")`, theme preload); dojo provides `dojo.addOnLoad` which gates the entire dynamic boot; lz-string/md5 are used later by save/telemetry code; system.js drives all dynamic module imports.
- Dynamic boot chain (strict): version.json/build.version.json → `config` (KGConfig schemes needed for theme CSS loading) → `i18n` (`i18nLang.init` must finish; `$I` keys used after) → `core` → the 26 modules in listed order → `initGame`. Every `_import` chains onto the previous promise, so imports are fully sequential, not parallel.
- Notable intra-list constraint: `js/ui` is imported before `js/space` because space relies on IReactAware defined there; `game` imports near the end; `js/toolbar` last.
- tests.html skips `config` and `i18n` entirely (imports `core` straight after libs), showing module import-time code tolerates missing i18n globals; only the runtime game page needs them.
- emulator.html depends on a separate `index_v2.html` served at 127.0.0.1:9999 (mobile experiment, not part of this shell).

## State & determinism
- `Math.random()` picks a loading message in `loadModule` (cosmetic only).
- Heavy time dependence in boot: `Date.now()` used as CSS/module cache busters (`?_=now`, `?rev_=<rev>` with extra `_Date.now()` when `invalidateCache`), and `version = "_" + Date.now()` in tests.html.
- Version stamping is network-dependent: `version` falls back to hardcoded "1.6.1.0" but is overwritten from `version.json` (also stored as `window.KGVersion`); `buildRevision` from `build.version.json`; alpha/beta channel suffix derived from URL string. Fetch failures fall back to the promise error path but boot continues.
- `LCstorage["com.nuclearunicorn.kittengame.ui"]` is read before config load to preload the saved theme (body class + stylesheet), so boot output depends on persisted UI state.
- `checkEldermass()` (date-based seasonal gifts) runs on every game load; `updateKarma()` applies persisted prestige state at boot.
- `?saveId=<guid>` makes boot non-default: storage is detached and the rest of init happens asynchronously after the cloud save arrives.

## Port notes / risks
- Hard-referenced DOM ids the F# shell (Elmish.Land index.html) must provide before GamePage/DesktopUI construction: `gamePageContainer`, `topBar`, `motd`, `devPanelFPS`, `devPanelCheats`, `headerToolbar`, `autosaveTooltip`, `saveTooltip`, `versionLink`, `newVersion`, `devModeButton`, `previewBanner`, `loadingContainer`, `loadingProgressBar`, `loadingProgressInfo`, `game`, `tooltip`, `leftColumn`/`leftColumnViewport`, `midColumn`/`midColumnViewport`, `gameContainerId`, `gameContainerHelp`, `rightColumn`, `calendarSign`, `calendarDiv`, `dev_boostCalendar`, `logLink`, `queueLink`, `observeButton`, `rightTabLog`, `gameLog`, `logFilters`, `pauseBtn`, `undoBtn`, `rightTabQueue`, `queueViewport`, `toggleCenter`/`toggleCenterIcon`, plus options/export/import ids (`languageSelector`, `notationSelector`, `schemeToggle`, `batchSize`, `exportData`, `importData`, `download-link`, `creditsDiv`, `optionsDiv`, `exportDiv`, `importDiv`, `appDiv`) and the `button_tooltip`, `column`, `right-tab(-header)`, `console-intro`, `links-block`, `dialog help/credits`, `scheme_*` CSS classes.
- Inline `onclick` attributes call the global `gamePage`/`game` variable directly (save/reset/wipe/cheats/dialog toggles); the port must either keep a global gamePage binding or rewrite all handlers into Elmish subscriptions — a systematic change across the skeleton.
- Boot-order constraints to preserve in the port: config before theme scheme loading, i18n dictionaries before any `$I` usage (16 `ui.loading.msg.N` keys) and before core, core before all feature modules, `js/ui`-equivalent before `js/space`-equivalent, GamePage construction only after every module is loaded.
- The i18n failure path just logs "Unable to load locales" and boot silently halts (no error UI) — the port should surface this.
- Theme system is imperative: dynamic `<link>` injection plus `body.scheme_<theme>` class, with the pre-config theme read straight from localStorage — needs an F# equivalent before the config module loads.
- Version stamping via two JSON fetches is a cache-invalidation mechanism (rev-based module URLs); in a bundled Fable build this largely disappears, but telemetry version/buildRevision fields and the `#versionLink` display still need values.
- emulator.html targets a nonexistent-in-recon `index_v2.html` mobile experiment (Framework7 styling) — safe to drop or defer; tests.html proves game modules import without config/i18n, useful for unit-test bootstrapping in F#.
- `#game` starts `display:none` and `#loadingContainer` visible; the swap happens inside initGame (or not at all in preview mode) — the port must replicate the loading-screen lifecycle.
