# Recon: js/resources.js (1178 lines) — recon unit recon-07

## Description
This file defines `classes.managers.ResourceManager` (a `dojo.declare` extending `com.nuclearunicorn.core.TabManager`), the central registry and accountant for every resource in the game. A static `resourceData` catalog (lines 21-536) declares ~44 resources (catnip, wood, coal, …, tMythril) with declarative flags: `visible`, `craftable`, `transient`, `persists`, `calculatePerTick`/`calculatePerDay`/`calculateOnYear`/`calculatePerTickAndDay`, `aiCanDestroy`, `type`, `tag`, `color`, `isNotRefundable`. The constructor deep-clones the catalog into per-game runtime objects carrying mutable `value`, `unlocked`, `maxValue`, `perTickCached`, `isHidden`, and indexes them in a name→resource map. Per tick, `update()` refreshes caps, applies unlock transitions, and adds `game.getResourcePerTick(...)` through the limit-checked `addRes` pipeline. Storage caps derive from `name+'Max'` effects multiplied through a layered ratio chain (paragon storage, CMBR, per-resource and global ratios, challenge modifiers). The manager also owns energy production/consumption accounting, price-affordability/payment helpers, redshift fast-forward support, karma/void special math, and save/load of a thin persistent subset. It renders nothing itself, but holds UI-adjacent state (hidden resources, pseudo-resources, lock) consumed by the res.js table.

5. Wrappers `addResPerTick` / `addResEvent` (differ only in paradox allowance) (lines 681-687)

12. Cap ratio multipliers: `addBarnWarehouseRatio` (silos catnip, barn/warehouse on raw materials) and `addResMaxRatios` (unicornTears branch, paragon, CMBR, `name+MaxRatio`, global/pyramid ratios, baseMetal, policy caps) (lines 896-973)

## Port notes / risks
- Hottest float-order path in the port: per resource per tick the exact sequence is `updateMaxValue(res)` → unlock/re-lock transitions → `addResPerTick(getResourcePerTick(name, false))`; `game.updateKarma()` runs after the entire loop; energy prod/cons after that. Iteration order must equal `resourceData` declaration order.
- `addRes` semantics must be replicated exactly: clamp to `Number.MAX_VALUE`; limit = `Math.max(prevValue, res.maxValue || Number.MAX_VALUE)` so existing overcap is preserved and removal is never blocked; `void` floored to integer; values `< 0.0000000001` zeroed; karma snapped via `getInverseUnlimitedDR` → round → `getUnlimitedDR(…, 5)`; return `addedValue` verbatim when unclamped (avoids double-rounding of the delta).
- Cap chain order: base `name+Max` effect → `addResMaxRatios` (unicornTears early-return branch → paragonStorageRatio → CMBR unless `opts.disableCMBR` → `name+MaxRatio` → `globalResourceRatio` + `pyramidGlobalResourceRatio` only if NOT normal-craftable and NOT transient → `baseMetalMaxRatio` for tag "baseMetal" → technocracyScienceCap/onAHillCultureCap) → negative `name+MaxChallenge` added via `getLimitedDR` normalized against `bld.effectsBase[name+'Max']` → floor at 0. sorrow overrides all: `17 + blsLimit` with inline value clamp; zebras add `karmaZebras+1` and are excluded from `addResMaxRatios`.
- baseCaps do NOT live in this file: raw `name+Max` effects come from the effects system (`bld.effectsBase` referenced at line 803). `addBarnWarehouseRatio` (silos: catnipMax × 1+barnRatio*0.25; wood/minerals/ironMax × 1+barnRatio × warehouseRatio; coal/titanium/goldMax × warehouseRatio) is defined here but invoked by the building/effects layer when assembling resMax — wire it at the same call site.
- Per-resource flags and what they gate: `calculatePerTick`/`calculatePerDay`/`calculateOnYear`/`calculatePerTickAndDay` are consumed by game.js aggregation, not here; `transient` excludes from production bonuses and the global/pyramid cap ratios (manpower/science/culture/faith etc.); `persists` (true/false/undefined) drives reset carryover in game reset logic; `craftable`+`visible` drive table placement in res.js; `isNotRefundable` (oil, kerosene, thorium) flips the default `isRefundable` closure installed in the constructor; antimatter has a custom `isRefundable` keyed on energy balance; `tag` values "baseMetal"/"metallurgist"/"chemist" route cap ratios and workshop upgrades.
- Unlock rules: a resource unlocks permanently once `value > 0`, except zebras/paragon/elderBox which re-lock at `value == 0`. `isHidden`/`isHiddenFromCrafting`/`showHiddenResources` are pure UI visibility and are persisted in saves.
- Energy details: consumption ratio is `(1 + energyConsumptionRatio + energyConsumptionIncrease) × 2` while challenge "energy" is active (LDR on that effect is defined in challenges.js); `getEnergyDelta` floors prod/cons at 0.25 and, if energy challenge is researched but not active, applies `1 - (1-delta)/2`. Winter projection calls the pasture building's `calculateEnergyProduction(game, season)` — that function lives in bld.js and must keep its exact signature and return values.
- `getAmtDependsOnStock` deducts stock immediately via `addResPerTick` and returns `amt/amtBeginni`; callers rely on that mutation order — do not make it pure without updating callers.
- `fastforward` touches only resources with truthy `perTickCached`, skips catnip when its cached per-tick is negative, uses `allowDuringParadoxes`+`preventLimitCheck`, and returns a limits map (`max(value, maxValue)`) for the later `enforceLimits` call in redshift.
- JS-isms to port carefully: loose equality (`res.value == 0`, comparing recomputed delta), `|| 0` coercion of undefined effects, `Number.MAX_VALUE` ≙ F# `float.MaxValue` (both IEEE double), deep-clone semantics (F#: immutable static defs + separate mutable runtime records).
