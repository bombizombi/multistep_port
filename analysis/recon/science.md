# Recon: js/science.js (2820 lines) — recon unit recon-05

## Description
science.js defines `classes.managers.ScienceManager` (a `com.nuclearunicorn.core.TabManager` subclass) plus the science tab's UI classes. The manager embeds two large static metadata arrays inline: `techs` (~60 technology definitions, lines 13-848) and `policies` (~55 policy definitions, lines 854-2160), each with i18n label/description, prices, `unlocks` maps, `blocks` exclusivity lists, and optional per-item `calculateEffects`/`evaluateLocks`/`onResearch`/`handler` closures. Manager methods cover lookup (`get`/`getPolicy` with a metaCache), dynamic price computation (leader discounts, challenge modifiers), save/load/reset, post-load re-unlock, and relation-policy unlocking. The UI half comprises `classes.ui.PolicyBtnController` (policy purchase with exclusivity blocking and confirmation flow), `classes.ui.PolicyPanel`, `com.nuclearunicorn.game.ui.TechButtonController`, and `com.nuclearunicorn.game.ui.tab.Library`, which renders all tech buttons, the policy panel, and an optional metaphysics (perks) panel. Purchase mechanics (paying, marking researched, firing `game.unlock`/`game.upgrade`) live in the inherited base controller in core.js, not here.

## State & determinism
- Mutable per-item flags on both arrays: `unlocked`, `researched`, `blocked` (policies); manager toggles `hideResearched`, `policyToggleBlocked`, `policyToggleResearched`; `metaCache` memoizes lookups; `effectsBase` holds two constants. Policy metas are also mutated at runtime: `lastCalculatedBonus` and string `description` rewritten (sharkRelationsMerchants L1431/1439), `upgrades` lazily replaced (upfrontPayment L2136-2142), `spiders.sells` trade list mutated (L1649-1654), `almostLimited` stamped on building metas (authocracy L935-937).
- No randomness and no Date/time usage in this file; all behavior is deterministic given game state (dynamic prices depend only on leader/challenge state; dragonRelationsAstrologers reads calendar cycle state but does not advance it).
- `save`/`load` round-trip only name/unlocked/researched (+blocked); everything else (effects, closures) is rebuilt from static definitions; `afterLoad` re-fires handlers/re-unlocks for researched items.

## Port notes / risks
- Unlock chains are declarative: `tech.unlocks` keys map to `game.getUnlockByName` types (tabs, buildings, jobs, tech, upgrades, policies, crafts, stages, zebraUpgrades, voidSpace, chronoforge, challenges, pacts, spaceBuilding, planet); the F# port must reproduce the full type table in game.js:6038 and the veto semantics — a target with `evaluateLocks` returning false silently cancels the unlock (no retry until something calls unlock again, e.g. `afterLoad` or `unlockRelations`).
- There is no "prev-tech" prerequisite field: gating is purely emergent — a tech becomes purchasable only after some researched tech lists it under `unlocks.tech`, and `resetState` (L2292) unlocks only `calendar`. Preserve list order and reverse-iteration semantics (`get` and `afterLoad` scan backwards).
- Policy exclusivity is a one-way latch: buying a policy sets `blocked = true` on every name in its `blocks` list (PolicyBtnController.onPurchase L2571-2576); `shouldBeBought` also latches blocking lazily (L2499-2505). Blocked is permanent for the run ("no way to unlock it other than reset", L851) — order of purchase matters and must be preserved.
- `evaluateLocks` closures encode hidden gates: building counts (workshop<2/factory<1 for scientificCommunism), factory>0 plus parent policy researched (liberalism/communism/fascism/sustainability/conservation), astronomy + parent foreign policy (knowledgeSharing etc.), embassy levels via `checkRelation(race, 20|10)`, space satellite counts, and MAUSOLEUM_PACTS feature flags. These run inside `game.unlock`, so the port needs them as pure predicates over game state.
- Tech purchase path is NOT in this file: `TechButtonController` inherits `buyItem`/`onPurchase` from core.js:2446 (`payPrice` → mark researched → `meta.handler(game)` → `game.unlock(unlocks)` → `game.upgrade(upgrades)` → `game.render()`). The port must decide where this shared purchase logic lives; science.js only specializes policies with `shouldBeBought` and an async confirmation `dojo.Deferred` flow (L2530-2543) that needs a synchronous/async replacement strategy in F#.
- `getPrices` is the single price authority for techs (UI reads it), but policies price via `PolicyBtnController.getPrices` with `1.25^policyFakeBought` scaling (L2437) — two different discount paths; scientist-leader discount and ironWill/blackSky gold surcharge (L2249-2253) and unicornTears surcharges (L2255-2277) apply only to techs.
- Handlers have load-time semantics: `voidSpace`/`cryptotheology` handlers are re-fired from `afterLoad` on every game load (comment L828-829) to re-unlock time-queue sources; `calculateEffects` functions are invoked from the effects-cache system, not only at purchase (e.g. radicalXenophobia calls `game.updateCaches()` inside its own calculateEffects — L1165 — reentrancy to watch).
- Some policies have side effects beyond effects: rewriting diplomacy trade lists (spiderRelationsChemists), dynamic descriptions (sharkRelationsMerchants/upfrontPayment), leader-job requirement gating (`requiredLeaderJob` checked in `shouldBeBought`), and the transkittenism aiLevel>=15 block (L2487) — keep these as on-research/purchase hooks, not static data.
- Static arrays must stay in file order: `Library.render` iterates `science.techs` linearly to build buttons, and several lookups/`save`/`load` assume index-stable metadata; `brewery` tech (marked "NOT USED ANYMORE", L85) is still in the list and must be kept for index alignment with saves (name-keyed, so mostly safe, but visible in UI list).
- SPACE_EXPL feature flag mutates the tech table at construction (L2172-2181); port as a data-load-time transformation, and note the commented-out `artificialGravity` link in dimensionalPhysics (L754) is intentional.
