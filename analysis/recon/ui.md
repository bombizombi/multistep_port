# Recon: js/ui.js (1197 lines) — recon unit recon-18

## Description
This is the shell/UI layer: a base `classes.ui.UISystem` interface (empty stubs the mobile build overrides) plus the concrete `classes.ui.DesktopUI` web implementation. It owns the full-page render cycle (tab strip, active-tab rebuild, React panels WLeftPanel/WMidPanel/WToolbar/WQueue), the per-tick `update()` patch cycle (calendar, undo button, tooltip GC, `ui/update` dojo topic publish), console log rendering, options/scheme UI, keybind handling, and i18n patching of static index.html elements. Despite being "shell", it secretly mutates game state in several places: the html-level click handler increments the `totalClicks` stat (achievement-relevant), `updateOptions`/`unlockScheme` push into `game.unlockedSchemes` (saved data), the filter checkboxes mutate `console.filters[].enabled`, and `updateNotation` writes `game.opts.notation`. It also persists its own prefs (fontSize, isCenter, theme) under a separate localStorage key. `isEffectMultiplierEnabled()` reads live keyboard state and is consumed by core.js effect display math, so input state leaks into calculation-adjacent display logic.

## State & determinism
- Own mutable state: activeTabId, keyStates (live keyboard), dirtyComponents[], cached DOM refs (fastHunt/fastPraise containers, tooltip handles), fontSize, isCenter, logMessagesToFade=15. Persisted separately in `LCstorage["com.nuclearunicorn.kittengame.ui"]` (fontSize, isCenter, theme) — not part of the game save.
- Secret game-state mutations: totalClicks stat increment (L189, achievements-relevant), `game.unlockedSchemes.push` in updateOptions (L843) and unlockScheme (L857), `game.opts.notation` write (L789), `console.filters[fId].enabled` writes (L1006), `game.unlockedSchemes = defaultSchemes` in relockSchemes (L862), `window.location.reload()` in applyLanguage.
- Model objects polluted with DOM: console message objects get `.span` DOM refs (L1042); tab objects get `.domNode` (L406/424) — must be dropped or isolated in the port.
- Time/randomness: no randomness; system-clock reads — April-1 easter egg (`new Date()` L598), `Date.now()` cache-buster in checkForUpdates (L1186); tick-relative timing: `game.ticks % 5 == 0` gates tooltipUpdateFunc (L636), undo ttl display divides by ticksPerSecond (L768). isEffectMultiplierEnabled reads live shift-key state, which changes displayed effect values in core.js (display-level, not save data).

## Port notes / risks
- Render/update split is the load-bearing contract: `game.render()` = full teardown+rebuild (rare, on tab switch/structural change) then immediate `ui.update()` to avoid flicker; `ui.update()` runs EVERY tick (even while paused) and must stay cheap. An Elmish/Fable port should map update() to an incremental per-tick view patch; doing a full re-render per tick will not scale (calendar innerHTML + document.title + tooltips).
- Move the totalClicks increment out of the DOM click wiring into the game event layer — it's a stat mutation that affects achievements; easy to lose in a UI rewrite.
- Keybinds (Shift+letter tabs, digit/arrow tab nav, Escape closing top dialog) and keyStates (shift → isEffectMultiplierEnabled feeding core.js display math) are environment/input state that must become keyboard subscriptions in the Elmish model, not DOM-global handlers.
- Event delegation points to replicate: tab-link clicks, filter checkboxes (mutate console.filters), scheme/notation/language selects, undoBtn tooltip (must attach exactly once — original leaks listeners), close-button dialog binding.
- renderConsoleLog is re-entrant: it calls `console.msg` to insert date headers, relying on stack ordering; messages array, maxMessages trimming, and filters are game state (saved), so the port must keep msg/trimming semantics in the model and treat spans/fading as pure view.
- updateOptions force-unlocks default schemes into game.unlockedSchemes — a save-migration behavior; dropping it breaks theme options for old saves. unlockScheme also emits an "important" console message.
- checkForUpdates (network fetch, 5-min timer) and the April-1 easter egg are droppable/voluntary; applyLanguage's full page reload should be replaced by in-place re-localization.
- The UISystem abstract stubs exist because a mobile UI subclasses it; the port can collapse the interface but should keep the seam where game.js calls ui.* so a headless/test UI can be substituted.
