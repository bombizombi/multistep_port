# Recon: js/village.js (6074 lines) — recon unit recon-02

## Description
This file holds the entire village subsystem of the Kittens Game: the `classes.managers.VillageManager` (a `TabManager` subclass), the per-kitten simulation `classes.village.KittenSim`, the kitten entity `com.nuclearunicorn.game.village.Kitten`, the expedition/biome system `classes.village.Map`, and a large block of dojo UI widgets (job buttons, hunt/festival buttons, loadouts, census panel, map overview, and the Village tab itself). The manager's `update()` runs once per game tick: it computes kitten birth progress and max population, kills kittens when catnip goes negative or in "winterIsComing" cold weather (throttled by `deathTimeout`), enforces job limits, handles anarchy leader removal, recomputes happiness, scales ambassador effects, and ticks the map (fauna spawns, exploration, squad combat). `KittenSim.update` accrues job skill XP per kitten (throttled by a population-based frequency), births kittens into a pool of seed-derived individuals, and handles skill decay / neural-network cross-training. State lives in the manager's aggregate `jobs[].value` counters mirrored per-kitten in `sim.kittens[i].job`, plus `nextKittenProgress`, `happiness`, `leader`, `maxKittens`, and the map's squad/biome objects; persistence is via `save`/`load` with three legacy kitten save formats. Jobs, traits, names/colors, biomes and default loadouts are big static inline catalogs.

## State & determinism
- Mutable manager state: `kittens/maxKittens` (mirror + cap), `happiness`, `deathTimeout` (tick countdown between starvation deaths), `leader` (kitten ref, restored on load), `senators` (vestigial: declared/reset, never populated; `isSenator` always forced false), `traits` (census filter cache), `resourceProduction` (lazy cache, rebuilt by `updateResourceProduction`), per-job `value`/`unlocked` on the shared jobs array, `sim.nextKittenProgress`, `sim.maxKittens`, `sim.hadKittenHunters`, map state (`currentBiome/lastBiome/activeMapId/hqLevel/energy/squad{hp,stats,efficiency,prevHp}/frame`), per-biome `val/on/cp/fauna`.
- `Math.random` uses: (1) `Kitten.rand` L1518 — fallback identity roll when a kitten is created without a seed (non-seeded legacy kittens); (2) `KittenSim.rand` L3445 — rolls each newborn's 0..999999 identity seed, which then deterministically drives name/trait/age/color/variety/rarity; (3) `Map.createFauna` L2251-2252 — ±15% jitter on mob level and HP at spawn; (4) `Map.attack` L2581 — ±10% combat damage variation. All four are combat/identity/lore jitter; kitten births themselves are NOT random (deterministic `nextKittenProgress` accumulator), starvation deaths are deterministic.
- `game.rand` (shared game RNG) uses: hit-chance roll in `attack` L2588, fauna name + 0.5%-per-tick spawn roll L2202/2207, pact "fractured" fake identity rolls L1352-1356 (plus a `randTimer` 10-50 ticks decremented per render).
- Deterministic seeded RNGs: `Kitten._createSeededRand` L1521 — Lehmer LCG (state = state*16807 % 2147483647) regenerating kitten identity from its saved seed; `Map.xmur3` L2470 and `Map.rand` L2490 (murmur-style finalizers) + `getStatAtLevel` L2496 — leader combat stats (atk/def/agi/str/spd/hp) derived purely from seed+level+statIndex, with an xmur3(name:surname) fallback for seedless leaders.
- The `deterministic` flag at L2248-2252: an optional third parameter of `Map.createFauna(biome, faunaName, deterministic)`. When true it forces both `levelJitter` and `hpJitter` to 1, i.e. it suppresses the two `Math.random` ±15% spawn-jitter rolls so the function returns the exact baseline mob level/HP curve. It controls nothing else; per its doc comment (L2243-2247) it exists so the balance simulator can read average fauna stats, and it defaults to false (jittered) in normal play.
- Hunt loot and biome rewards are probabilistic via `game.math` helpers (binomial/geometric/Irwin-Hall) and diplomacy's `_fuzzGainedAmount` — these live outside this file but their outputs land here.
- No `Date`/`Date.now` usage anywhere in the file; all timing is tick-based (`game.ticks`, `deathTimeout`).

## Port notes / risks
- Dual bookkeeping: aggregate `jobs[i].value` must stay in sync with per-kitten `kitten.job`; desync is patched reactively (`clearJobs(true)` when `getFreeKittens()` < 0, "out of synch, refresh instantly" calls to `updateResourceProduction`). An F# port should make job counts derived state to avoid this class of bug.
- Kitten identity is seed-derived: the Lehmer LCG in `_createSeededRand` and the exact attribute-roll order in `_generateAttributes` (name, surname, trait, age w/ 30% extension, 10% color, 10% of colored → variety, 5% rarity +10% extra) must be reproduced bit-exactly or every existing save regenerates different kittens. 32-bit overflow semantics of the LCG/hash functions need care in F# (use uint32/int64 wrapping).
- Three legacy kitten save formats (seeded, ssn-compressed via base-100 packing with 2^53 limits, uncompressed) plus a 20001 skill cap clamp on load and a biome `level→val/on` migration — save compatibility is a hard requirement.
- RNG provenance is mixed: combat hit rolls and fauna spawns use the shared `game.rand` stream, while damage and fauna-jitter use raw `Math.random`, and leader stats/kitten identity use their own hashes. A deterministic port must inject three separate RNG sources at exactly these call sites or replays will diverge.
- Side effects inside "calculate" functions: `priest.calculateEffects` unassigns all priests under atheism; `updateResourceProduction` demotes the leader under theocracy; several challenge checks mutate leader/jobs mid-tick. Ordering relative to the policy/challenge evaluation matters.
- `KittenSim.update` throttles skill accrual by population (every 1/5/10/20 ticks, using `game.ticks % frequency`) and multiplies XP by `frequency` afterwards; fastforward (`times != 1`) bypasses the throttle — reproduce both paths or long-run skill totals drift.
- Production math is float-order-sensitive: `updateResourceProduction` accumulates per-kitten diffs in array order and applies happiness/leader/rank multipliers in a specific sequence; `getStyledName`/census build HTML strings inline (DOM coupling to strip).
- Hidden globals: writes `game.diplomacy.cachedAmbassadorEffects`, `game.globalEffectsCached["exploreRatio"]/["mapPriceReduction"]`, pokes `game.villageTab.updateTab/requestCensusRefresh` and `game.workshopTab.updateTab` from deep inside logic; kongregate stats and `game.stats` counters increment on births/deaths.
- The UI block (roughly L2693-6074 plus loadouts L3773-4534) is ~45% of the file and is dojo-widget-heavy (links lists, tooltips, pagination with static cross-tab state in `Census.statics`, `dojo.publish`); port it last as a thin shell over the core units.
- Loadout `setLoadout` is an intricate redistribution algorithm (ratio scaling, floor-then-ensure-1 pattern, engineer factory limits, leader trait matching); theocracy/anarchy interactions are patched in with special cases — port with exact branch order and add unit tests before touching it.
