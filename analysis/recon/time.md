# Recon: js/time.js (2791 lines) — recon unit recon-09

## Description
Defines `classes.managers.TimeManager` (extends `com.nuclearunicorn.core.TabManager`), the chronoforge/voidspace meta manager: two static upgrade tables (chronoforgeUpgrades, voidspaceUpgrades), the chronoheat system (spare `heat` pool vs `blastFurnace.heat` furnace heat), temporal flux storage/acceleration ("Tempus Fugit"), the three TC-shatter algorithms (`shatter`, deprecated `shatterInCycles`, `shatterInGroupCycles`), redshift (wall-clock offline catch-up via `calculateRedshift`/`applyRedshift`), and undo handling for time purchases. It also defines the entire build-queue system: `classes.queue.manager` (cap, sources, ETA estimation, per-tick auto-buy) plus UI classes (`TimeTab`, `QueueTab`, `TimeControlWgt`, `ChronoforgeWgt`, `VoidSpaceWgt`, `ResetWgt`, shatter/use-heat buttons and their controllers). The queue's per-tick `update()` reuses the real button controllers' `buyItem` from every subsystem, which makes this file a hub touching nearly all other managers. Wall-clock time (`Date.now`) is load-bearing here: save timestamps, offline flux gain, and redshift all derive from it.

## State & determinism
- Mutable manager state: `flux` (years skipped stat), `heat` (spare chronoheat pool, soft-capped by `heatMax` effect — overcap shown red and priced), `isAccelerated`, `timestamp` (wall-clock anchor), `testShatter` (persisted algorithm selector: 0=shatter, 1=shatterInGroupCycles), `queue` (`queueItems`, `queueSources`, `queueSourcesArr`, `alphabeticalSort`, `cap`/`baseCap`), per-CFU `val/on/heat/delayTicks/isAutomationEnabled/unlocked` (blastFurnace.heat and controlledDelay.delayTicks are live tick state), per-VSU `val/on/unlocked`.
- Date.now usages (all wall-clock, all affect game outcomes): line 36 `save` — timestamp stored as `game.pauseTimestamp || Date.now()` (pauseTimestamp makes paused saves deterministic); line 82 `load` — fallback `saveData.timestamp || Date.now()`; line 111 `gainTemporalFlux` — offline delta converted to temporalFlux resource (real reward); line 136 `resetState` — resets anchor; line 236 `calculateRedshift` — per-tick delta drives redshift catch-up (2000 ms = 1 in-game day, ignored if < 3 days, capped at 10 or 40 years). `new Date()` at lines 990/994/999/1003/1008/1012 is dev-benchmark only (compareShatterTime).
- Math.random: none in this file. Indirect randomness: `ShatterTCBtnController.doShatter` calls `game.createRandomVarietyAndColor(100, 0)` to randomize leader fur color when the `whatYearIsIt` badge fires (day < 0 && amt >= 500) — a joke behavior, deterministic port can keep or stub it.
- No shatter/flux outcome depends on randomness otherwise; all shatter math is closed-form/deterministic given game state. Save/load round-trip of `heat`, `delayTicks`, `isAutomationEnabled`, `testShatter` matters for exactness.

## Port notes / risks
- Heat update order is subtle: `update()` transfers spare heat into the furnace BEFORE running CFU actions and only then calls `calculateRedshift`; `applyRedshift` does a second, different heat transfer (`daysOffset * ticksPerDay * heatPerTick`, capped by remaining spare heat, multiplied by efficiency) and may auto-shatter. Both paths must be ported or furnace state diverges.
- Blast furnace auto-shatter hardcodes `self.heat >= 100` (not the `heatMax` effect) and a 5-per-tick limit (raised to `shatterYearBoost` only when temporalPress automation is on and `testShatter==1`); `controlledDelay.delayTicks` decrements even when automation is off (explicit comment says intentional, unaffected by Tempus Fugit).
- `getPricesMultiple` is a closed-form discrete integral of two growing penalties (heat 1%/unit above heatMax, Dark Future 0.00001/year) split into constant/linear/quadratic segments with ceil/clamp edge cases — the most delicate pure math in the file; bulk shatter prices will drift if reimplemented approximately.
- `shatter` vs `shatterInGroupCycles` produce different accumulation granularity (per-year vs 5-year/cycle chunks with `calculateMilleniumProduction`); `testShatter` is saved, so the active algorithm is player state. shatterInCycles is deprecated but shipped; port can likely drop it and the benchmark.
- AI Apocalypse in `shatterInGroupCycles` contains the typo `res.MaxValue` (capital M, ~line 936) making that branch effectively always false, plus geometric-progression destruction math with a negative `aiDestructionMod` and a `delta`-tracking hack; decide bug-for-bug vs fixed and document.
- QUEUE_REDSHIFT path semantics differ: it calls `applyRedshift(days, ignoreCalendar=true)` in year-aligned chunks (daysNeeded floored at 1 day and ceil-aligned to whole years to avoid an infinite loop) and only at the end does one `calendar.fastForward(daysOffset)` for events; the non-queue path fast-forwards the calendar with production in a single pass.
- Save timestamp semantics: `save` uses `pauseTimestamp || Date.now()`; `load` calls `gainTemporalFlux(ts)` BEFORE setting `this.timestamp`, so the first `calculateRedshift` after load won't double-count the offline span — preserve this ordering. `_forceChronoFurnaceStop` only mutates the save copy, not live state.
- Queue `update()` buys the head item by instantiating the real UI controller and calling `buyItem(model, {boughtByQueue: true})` — queue logic is entangled with the UI controller layer; the F# port needs the buy/price logic extracted from DOM-bound controllers or an adapter, and `getQueueElementControllerAndModel` is a 15-case switch to replicate.
- `getFirstItemEtaDay` returns `[eta, calculated]` and treats missing storage (`res.maxValue < price.val`), non-positive production delta, and engineer craft-countdown alignment specially; QUEUE_REDSHIFT correctness depends on it exactly.
- Minor defects: `unlockAll` references nonexistent `this.cfu` (would throw; dev-only), `updateQueueSourcesArr` ends with a stray no-op `self.queueSourcesArr;`, and `temporalPress.calculateEffects` mutates `description`/`priceRatio` (behavior inside static defs, like other managers) — CFU `getEffect` provider zeroes all CFU effects until workshop `chronoforge` is researched, which must be preserved for Energy challenge fairness.
