# Recon: js/buildings.js (3798 lines) — recon unit recon-03

## Description
Defines the Bonfire-tab building system of the Kittens Game. It contains two small metadata wrapper classes (`classes.Metadata`, `classes.BuildingMeta`) that give stage-aware read/write access to a building's definition, and the big `classes.managers.BuildingsManager` (a `com.nuclearunicorn.core.TabManager` subclass) that owns the static `buildingsData` array (40 buildings, 5 of them staged: pasture/solarfarm, aqueduct/hydroplant, library/dataCenter, warehouse/spaceport, amphitheatre/broadcasttower). The manager implements price math (`getPrices`, `getPriceRatio` with CostReduction/ratio effects and challenge overrides), the per-tick `update` loop (unlock checks + per-building `action` callbacks), unlock rules, pollution simulation, save/load/reset, fastforward, undo, and the `gatherCatnip`/`refineCatnip` helpers. Per-building behavior lives as function-valued fields inside `buildingsData`: `calculateEffects` (recomputes an effect dict from game state), `action` (per-tick scaling of consumption/production against stock, e.g. smelter/calciner/mint/brewery), plus `updateEffects` (aiCore only), `canSell` (aiCore) and helpers. The rest of the file is UI: gather/refine catnip button controllers, `BuildingBtnModernController` (buy/sell/toggle bookkeeping with undo + stats/telemetry), `StagingBldBtnController` (stage up/downgrade with full refund), `StagingBldBtn`, and the `BuildingsModern` tab that renders buildings grouped/filterable.

**calculateEffects dispatch:** function-valued fields are carried by the data units buildings-03..07 (plus `updateEffects` on aiCore, `action` on 13 buildings). They are never called inside buildings.js by name from a central dispatcher: `game.upgrade(list)` in game.js (lines ~6097-6124) looks items up by id/type and calls `item.calculateEffects(item, game)` or `item.updateEffects(item, game)` (never both) with caches refreshed before/after; buildings.js calls it directly only in `deltagrade` (line 3568) and `undo` (via `game.upgrade`). aiCore is the sole `updateEffects` building — any port must reproduce the calculate-vs-update exclusivity rule.

## Port notes / risks
- Price formula exact shape (buildings-08): `ratio = base + getLimitedDR(namePriceRatio + priceRatio + mapPriceReduction, base-1)` where `base = priceRatio`; then `cost = baseVal * pow(ratio, val + fakeBought) * (1 - getLimitedDR(nameCostReduction, 1)) * (1 - getLimitedDR(resCostReduction, 1))`; `fakeBought = getEffect(nameFakeBought) + additionalBought` (postApocalypse pollution housing). CostReduction effects are clamped to 1 *after* summation for the building-level one but per-resource-line individually for resource ones — keep both clamps. `multPriceRatio` (spaceport starchart) multiplies on top: `cost *= pow(multPriceRatio, val+fakeBought)` — only inside the `priceRules` branch. Challenge patches (blackSky/pacifism/postApocalypse) apply only in the `priceRules` branch; the early-exit branch (`!priceRules && !unicornTears`) skips them — preserve the branch structure exactly.
- `getEffect` dispatch on the manager is name-shape-driven: suffix `Max` scales by `val` (except library whose scienceMax must then be handled inside calculateEffects manually), biolab `Ratio` effects scale by `val`, everything else by `on`; `coalRatioGlobal` is raw (not multiplied). This suffix convention is load-bearing — an F# port should make it explicit data, not string matching.
- Stage switching (`deltagrade`) sells the entire stack first (undo events ordered deliberately), resets `val`/`on` to 0, clamps `stage`, recalcs `calculateEffects`, and calls `time.queue.onDeltagrade`; `BuildingMeta` caches meta per stage and must be invalidated on stage change (the `get`/`set` cache-invalidation via `_metaCacheStage` is subtle).
- Effect-keys catalogue: ~90 distinct keys appear (perTickBase/Con/Prod/Autoprod families, `*Max` storage, `*Ratio` global/local, demand ratios, energyProduction/Consumption, cathPollutionPerTickProd/Con, festival/gflops/aiLevel, storage bonuses, zebraPreparations). Several are declared with 0 values purely so they register in `effectsCachedExisting` (see `setEffectsCachedExisting` which also registers stage effect names) and for tooltip display.
- Unlock callback paths: `unlocks` ({tabs, jobs, upgrades, policies, crafts, zebraUpgrades, spaceBuilding, voidSpace, challenges}) and `upgrades` ({buildings, policies, spaceBuilding, challenges, voidSpace}) are consumed by game.js `unlock`/`upgrade`, not here — but `calculateEffects` also *calls* `game.upgrade(self.upgrades)` directly (ziggurat line 2088, zebraForge line 2294, zebraOutpost.action line 2216) and `time.queue.unlockQueueSource` (library/workshop/temple/zebraWorkshop/ziggurat), which re-enters this file's data. Watch for recursion/ordering.
- `action` semantics: runs every tick in `update()` only when `on > 0` (biolab/aiCore excepted), returns stock-limited `amt` (0..1) used to scale consumption/production effects and set `lackResConvert`; effects are split into `effects` (displayed, scaled) vs `effectsCalculated` (full-rate baseline) — this two-dict pattern (smelter/calciner/biolab/brewery) must be preserved or tooltips and production both break.
- `gatherCatnip` is trivially `catnip.value++` per click; the gather/refine buttons live in the buildings tab and undo integration registers workshop-id events (catnip->wood refinement is treated as a craft for undo purposes).
- `BuildingsManager.getPricesWithAccessor` reads `bld.get("val")` through the stage accessor while game code elsewhere writes `val` onto the raw meta; the BuildingBtnModernController syncs `model.metadata.val/on` back into the accessor — port the val/on ownership model carefully (raw meta object is the single source of truth).
- The tab `BuildingsModern.render` is DOM-heavy (dojo.create/connect); the F# port likely replaces it, but keep the pure logic (group visibility, aggregate filter predicates, unroll order) testable and separate from rendering.
