# Recon: js/settings.js + i18n.js + config.js (~600 lines) — recon unit recon-16

## Description
These three files form the options/localization/configuration layer of the game. `js/settings.js` (393 lines) declares `classes.managers.SettingsManager` (extends `com.nuclearunicorn.core.TabManager`), a metadata-driven registry of ~23 boolean options stored in `game.opts`, plus `com.nuclearunicorn.game.ui.tab.SettingsTab` which renders them as checkboxes in the options screen. `i18n.js` (191 lines) declares `com.nuclearunicorn.i18n.Lang`, which boots the locale system: it detects/persists the user language, asynchronously loads `res/i18n/en.json` as the base dictionary and overlays legacy + crowdin translations, exposes lookup via the global `$I(key, args)` function and singleton `i18nLang`. `config.js` (9 lines) declares `classes.KGConfig` with an instance field misleadingly named `statics` holding the locale list, color-scheme list, default schemes, notations, and a `disableWebWorkers` flag. Notably, the SettingsManager intentionally handles only boolean options — non-boolean options (language, notation, color scheme) live directly on `game.opts` and are persisted by game.js, not here. The index.html boot order (config → i18n → locale-load promise → core + module list including js/settings) is what makes the eagerly-evaluated `$I(...)` labels in `settingsArr` work at script-load time.

## Functionality
1. `SettingsManager` declaration with an extensive "how to add an option" metadata contract (name, defaultValue mandatory; label, tooltip, mobileTitle, mobileDesc, isExtra, triggerUpdateUI, devModeOnly, showOnlyIfKSDetected, onChange optional) — settings.js 1–45.
2. `settingsArr` catalog of 23 boolean options (useWorkers, forceHighPrecision, usePerSecondValues, usePercentageResourceValues, showNonApplicableButtons, usePercentageConsumptionValues, highlightUnavailable, hideSell, hideDowngrade, hideBGImage, tooltipsInRightColumn, noConfirm, IWSmelter, disableTelemetry, enableRedshift, disablePollution, enableRedshiftGflops, useLegacyTwoInRowLayout, useSwipeNavigation, ksEnabled, forceLZ, compressSaveFile, hodl, disableCMBR), each labeled via `$I` evaluated at load time — settings.js 46–188.
3. `hodl` option's `onChange` side effect: cashes out the b-coin stash at the old price via `game.diplomacy.sellBcoin(oldValue)` to prevent arbitrage — settings.js 175–183.
4. Constructor + `registerSettings` (validates name is a string and defaultValue is a strict boolean, skips bad entries with console.error) and `resetState` (revert all to defaults) — settings.js 190–227.
5. `save` is a deliberate no-op (persistence handled by game.js); `load` only performs the migration `saveData.game.useWorkers` → `saveData.game.opts.useWorkers` — settings.js 229–251.
6. Accessors: `forEach` over the registry, `get`/`set` (accept metadata object or name string; write through to `game.opts[name]`), `getSetting` (lookup via inherited `getMeta`); `set` fires `meta.onChange(game, old, new)` only when oldValue is defined and actually changed — settings.js 253–299.
7. `SettingsTab.render` fills `#booleanOptionsNormal` / `#booleanOptionsExtra` DOM containers, hiding options that are devModeOnly / showOnlyIfKSDetected / label-less unless `game.devMode`; routing by the `isExtra` flag — settings.js 324–348.
8. `SettingsTab.renderSetting`: creates checkbox input + label (falling back to mobileTitle then raw name), optional "(?)" hover hint wired through `UIUtils.attachTooltip`, onclick handler that calls `settingsManager.set`, re-syncs the checkbox, and re-renders options when `triggerUpdateUI` — settings.js 350–393.
9. `Lang` constructor: builds `availableLocales = ["en", ...KGConfig.statics.locales]` and a hardcoded 22-entry code→native-name label map — i18n.js 6–50.
10. `init`/`_init`: optional Cordova `navigator.globalization.getPreferredLanguage` detection, then reads persisted language from `LCstorage["com.nuclearunicorn.kittengame.language"]`, else picks the best match for the OS locale (split on `[-_]`, lowercase first part, match against availableLocales) and persists it; loads `res/i18n/en.json?_=<timestamp>` as base, then if language ≠ en merges legacy `res/i18n/<lang>.json` and then `res/i18n/crowdin/<lang>.json` over it via `$.extend`, resolving a jQuery Deferred promise — i18n.js 52–142.
11. Locale accessors (`getAvailableLocales`, `getAvailableLocaleLabels`, `getLanguage`, `isAvailable`) and `updateLanguage` which sets `language` and persists it to LCstorage without reloading dictionaries — i18n.js 144–168.
12. `msg(key, args)`: dictionary lookup; missing key logs console.error and returns literal `"$"+key` (origin of the `$I` name); otherwise sequentially replaces `{0}`, `{1}`, … placeholders with args; file ends by creating the global `i18nLang` singleton and `$I` function — i18n.js 170–191.
13. `classes.KGConfig` "statics": `disableWebWorkers: false`, 18 locales, 26 color schemes with a 10-entry `defaultSchemes` subset, and `notations: ["si","e","sie"]`; instantiated fresh (`new classes.KGConfig()`) by i18n.js, index.html, and UI code — config.js 1–9.

## Dependencies
- calls into: settings.js → TabManager (`forEach`, `getMeta`), `$I`/i18nLang, `UIUtils.attachTooltip`, `game.diplomacy.sellBcoin`, `game.ui.updateOptions`, `game.devMode`, dojo/jQuery DOM helpers, index.html containers. i18n.js → `classes.KGConfig`, jQuery (`$.getJSON`, `$.Deferred`, `$.extend`), global `LCstorage`, Cordova `navigator.globalization` (optional). config.js → nothing (pure data).
- called by: `$I` is called from virtually every module (thousands of sites) and eagerly at declaration time in settings.js and elsewhere; `i18nLang.init(now)` is driven by index.html's boot sequence (after config.js import, before core/game modules load); `SettingsManager` is instantiated by game.js as `game.settings` (its save/load hooked into the game save cycle) and consumed by SettingsTab and ui.js; `KGConfig.statics` is consumed by i18n.js, index.html theme preloading (`schemes`), and ui.js (notations, schemes).

## State & determinism
- Mutable state: `game.opts[name]` values (the real option store, owned by the game page, persisted by game.js — not by this manager); `Lang.language`, `Lang.messages`, `Lang.platformLocale`, `Lang.availableLocales`; localStorage keys `com.nuclearunicorn.kittensgame.language` (exact key used: `com.nuclearunicorn.kittengame.language`) and the separate `com.nuclearunicorn.kittengame.ui` blob holding the theme (`{theme:...}`, read in index.html, not in these files).
- Randomness: none in any of the three files. Time usage: only the cache-busting query `?_=<timestamp>` passed into `Lang.init` for JSON fetches (wall clock, network-only; no gameplay impact). All logic is deterministic given inputs.

## Port notes / risks
- Eager `$I` evaluation: `settingsArr` labels (and other modules' static metadata) call `$I` at script-load time. This only works because index.html loads config.js, then i18n.js, awaits the dictionary-load promise, and only then loads `js/settings` and the rest. In F#, either translate lazily (store i18n keys, resolve at render) or reproduce this strict boot ordering — otherwise every label renders as the `"$key"` fallback.
- `$I` fallback semantics: missing key → `console.error` + return literal `"$" + key`; this is load-bearing (also masks load-order mistakes). Placeholder substitution is a naive sequential `String.replace("{i}", args[i])` — only first occurrence per index, args not stringified/escaped, extra `{n}` left as-is; args are optional.
- Typo bug to decide on: `_init`'s re-entrancy guard checks `this._deffered` (line 76) but the deferred is assigned to `this._deferred` (line 103) — the guard never fires and a double `init` would start duplicate dictionary loads. Replicate faithfully or fix deliberately.
- Dictionary chain: `en.json` is always the base; legacy `<lang>.json` is merged first, then crowdin `<lang>.json` overrides it (later `$.extend` wins). If the base `en.json` fetch fails, only an error is logged and `messages` stays undefined — every subsequent `$I` would throw or fall back; the port should make this failure explicit. `updateLanguage` persists the choice but does NOT reload dictionaries (language switch requires a reload / is handled elsewhere).
- Boolean-only manager: SettingsManager manages 23 booleans; non-boolean options (language, notation, color scheme, etc.) are read/written directly on `game.opts` and persisted by game.js's save code. `save` is a no-op and `load` only migrates legacy `game.useWorkers` → `game.opts.useWorkers` — keep this split or the F# save loader will miss fields.
- Gameplay-affecting vs display-only options: notation (`si`/`e`/`sie`) and `forceHighPrecision` are number-formatting/display only (no production-math effect); `disablePollution` explicitly has no functional effect (UI hiding only). Gameplay-affecting: `useWorkers`, `IWSmelter`, `enableRedshift` (+`enableRedshiftGflops`) for offline progression, `noConfirm`, `forceLZ`/`compressSaveFile` (save encoding), and `hodl`, whose onChange must fire `diplomacy.sellBcoin(oldValue)` on a genuine toggle (suppressed during registration/reset since oldValue is undefined).
- Scheme persistence is split: the scheme list lives in KGConfig but the selected theme is stored in a separate LCstorage blob `com.nuclearunicorn.kittengame.ui` as `{theme:...}` and preloaded as a CSS class before the game boots (index.html ~170–186) — not in `game.opts` and not in these files; a naive port that puts it in opts will break theme-before-boot. `defaultSchemes` is a 10-entry subset used presumably for a defaults picker.
- Minor: `ksEnabled` (showOnlyIfKSDetected) and `disableCMBR` (devModeOnly) are hidden/legacy flags — the KS integration can likely be stubbed out; `KGConfig.statics` is an instance field (a fresh object per `new classes.KGConfig()`), so in F# it should just be a static record/module constant.
