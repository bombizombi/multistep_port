# PLAN — Kittens Game → F# (Elmish.Land), multistep port

**Mission.** Reproduce Kittens Game v1.6.1.6 (`orig_project/kittensgame`) in F# under
Elmish.Land 2.0, incrementally, with *objective* evidence of equivalence — not vibes.
Progress lives on disk (`ledger/`, `analysis/`, `reports/`) so any LLM session (and any
human) can resume exactly where the last one stopped.

**Non-goals.** No general JS→F# translator. No pixel-perfect DOM diffing. No rewriting
the game to be "better" while porting — behavioral fidelity first, deliberate divergences
only via a recorded decision in `ledger/decisions.md`.

**Working rule:** work happens in sessions that complete **at most 2–3 work units**, then
stop and write a session report. Never expand scope mid-session.

## 4. The unit of work

Not the file — the **work unit**: a symbol-sized slice of behavior, small enough that one
session can translate + compile + test it, and the ledger can say precisely what it covers.

- **Id:** `<area>-NN`, area = orig file stem or system name (`village-03`, `calendar-01`,
  `oracle-02`, `bootstrap-01`).
- **Layer (mandatory):** `core` = pure logic, oracle-diffable (production math, prices,
  effects, unlocks, craft, jobs, calendar, combat rolls under seeded RNG) · `shell` = UI/
  DOM/React glue (Feliz views, tab wiring) · `data` = static catalogs (specs) · `infra` =
  harness/tools/build.
- **Status:** `not-started → in-progress → translated → verified` (+ `blocked`).
  `verified` requires: `dotnet build` green AND (core) oracle agreement for the unit's
  fixture set AND ledger updated AND session report written.
- **Contract:** every core unit gets a short contract *before* implementation (purpose,
  inputs, outputs, side effects, nondeterminism used, error conditions, invariants) —
  stored in the ledger entry. Judged against contract + orig, not "looks right".
- **Dependency edges:** units declare `depends-on` so `reports/progress.md` can list what
  is *next available* vs blocked. Rough order: data specs → resource/production core →
  calendar → buildings/effects → unlocks → craft → village/jobs → hunting/trade →
  religion/space/time/prestige → shells last per tab.

## 5. Phases and exit criteria

**Phase 0 — Bootstrap (this session).** Structure created; scan generated; scaffold
builds; protocol + ledger seeded. *Exit: kittens_land `dotnet build` green, analysis/*.json
exist, ledger lists Phase 1 units.*

**Phase 1 — Reconnaissance.** LLM recon sessions, 2–3 files each: for every game-role file
in `analysis/files.json` write (a) semantic description of its functionality into
`analysis/inventory.md`, (b) split it into work units with symbols+line ranges + layer +
dependencies in `analysis/work-units.json` / ledger. Mechanical half (lines, symbols,
nondeterminism) is already done. *Exit: every game-role file has description + units;
dependency graph covers 100% of orig game lines (units reference symbols, lines are
orientation).*

**Phase 2 — Deterministic oracle.** Build `oracle/runner/`:
- **orig side:** Node harness on top of `test/setup.js` stubs — mocked dojo, in-memory
  localStorage, seeded Math.random, fake clock advanced 1000 ms per tick, tick driven
  synchronously (no Web Worker), KGNet stubbed (orig ships `tools/mock-kgnet` for this).
  Runner executes a *scenario* (strategy script: `tick action` lines, vocabulary
  `gather|buy|craft|assign|research|…` mapped through UI controllers exactly like
  `test/game.test.js` does) and dumps state snapshots at checkpoint ticks (JSON: resources,
  buildings, jobs, techs, upgrades, calendar, log events, RNG draw count, save blob).
- **port side:** same scenario executed by the F# sim core (console runner under .NET;
  same runner is compiled via Fable for the browser later).
- **diff:** `tools/diff-snapshots.js` compares snapshot JSONs with float tolerance 0
  (exact) and reports first divergence with context.
*Exit: one full scenario (fresh start → temple, ~627k ticks) runs identically twice on
orig (determinism self-check) and produces golden fixtures in `oracle/fixtures/`.*

**Phase 3 — Incremental migration.** Sessions of 2–3 units, strictly in dependency order,
core before shell. Every core unit: implement → `dotnet build` → run unit's scenarios →
diff vs golden → record pass/fail in ledger + `reports/discrepancies.md` (failures are
logged and diagnosed, never silently "fixed" by tuning the test). Every session ends with
a session report. *Exit: 100% of core units verified.*

**Phase 4 — Closure.** All units verified; long-run scenarios agree (multi-thousand-tick
traces including save→load roundtrip); Fable build (`elmish-land build`) green; browser
smoke test of every tab; coverage report shows every orig file mapped; final review pass
over `discrepancies.md` for accepted divergences. *Exit: ship it.*

## 6. JS→F# conversion patterns (adopted from elmishKittens PORT_PLAN.md — proven)

1. Untyped meta objects → F# records for static defs + `Map<string,float>` for effects,
   `Map<string,XState>` for live collections. Never `obj`/`dynamic`/reflection.
2. `dojo.declare` class → F# module: `Types` + `Data` + `Engine` (pure functions).
   Mutable `this.*` → immutable `Model` threaded through `update`.
3. Function-valued fields (`calculateEffects`, `action`) → named pure functions in
   `Engine`, dispatched on def `Name`. Keeps data serializable for save/load.
4. `game.getEffect(name)` → fold over building/upgrade maps in `Engine`.
5. TabManager subclasses → one Engine section + one Feliz view section per tab.
6. `setInterval` tick → Elmish subscription dispatching `Tick` msgs; core never reads
   wall time (tick index in, state out).
7. Labels hardcoded English first; i18n dictionary swap later without touching Engine.

**Numeric discipline (added):** JS numbers and F# `float` are both IEEE-754 doubles —
bit-identical *if operation order is preserved*. Therefore: port arithmetic in the same
order, no algebraic "cleanup" while porting; `Math.floor(x)` → `floor x` (mind negatives),
JS `x|0` → `int x` (truncation); record any unavoidable rearrangement as a decision.

## 7. Determinism & oracle rules

- Full nondeterminism census: `analysis/nondeterminism.json` (generated). Categories:
  RANDOM (27 `Math.random` hits), TIME (35 `Date` hits), STORAGE (localStorage saves),
  TIMERS (Web-Worker tick), NETWORK (KGNet), ENV.
- **Orig stays pristine.** No `orig-deterministic/` fork: the harness injects fakes at
  runtime (monkey-patch `Math.random` → seeded PRNG; `Date` → fake clock; localStorage →
  memory). A fork would double maintenance and drift; injection needs zero changes to
  orig. Revisit only if the census reveals call sites injection can't reach.
- Every scenario run records: RNG draw count + seed, tick count, snapshot hashes. If two
  runs of orig ever disagree, the oracle itself is broken — fix that first.
- Port core units must consume the same seeded PRNG stream (same draw order), not just
  the same seed — draw count per tick is part of the snapshot.

## 8. Risks (ranked)

1. **Float order divergence** — biggest source of mid-run snowballing mismatches. Fight
   with §6 numeric discipline + short checkpoint intervals (diff every N ticks, not only
   at the end, so divergences localize).
2. **Hidden DOM dependencies in game logic** — orig mixes logic with `game.page.ui`
   touches. Recon must flag every such symbol; core units must stub/extract, not port
   the DOM touch.
3. **Save-format archaeology** (load path) — orig load is the most defensive code in the
   repo; schedule it as its own units with recorded saves as fixtures (orig ships
   `test/res/save.js` — reuse).
4. **RNG draw-order mismatch** — port calls `rand` once more/fewer → everything after
   diverges. Draw count is in every snapshot to catch this immediately.
5. **Scope creep per session** — controlled by the 2–3 unit rule + session reports.

## 9. Conventions

- Ledger is the single source of truth for status. `reports/progress.md` is generated
  *from* it (or kept in sync manually if generation isn't built yet — note which).
- Everything in `analysis/` is regenerable or annotated; never hand-edit generated files.
- One branch of truth: this directory is a git repo; commit after every session.
- Orig is read-only. If we ever think "let me just tweak orig" — no. Decision goes to
  `ledger/decisions.md` first.
